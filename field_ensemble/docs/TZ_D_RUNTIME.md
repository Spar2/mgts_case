# Задача D. Режим климатики по одному ряду температуры

Модуль `dts/runtime.py`. Сравнение — `scripts/bench_runtime.py`, числа — `artifacts/eval/runtime.json`. Флаг по умолчанию выключен: без него ширина скаляров и граф совпадают с `dts.models.EventNet`. В `dts/events.py`, `dts/infer.py` и `models_release/` ничего не менялось.

## Что считается

`runtime_features(series, time_s)` описывает ряд средней температуры зоны пассивной моделью первого порядка

    dT/dt = −k (T − T_inf).

Коэффициенты — IRLS Хубера на отсчётах с малой кривизной `|d²T/dt²|` (квантиль 0.4, края сглаженного ряда не входят в подгонку). Активный отсчёт — где модуль остатка производной больше `3 · MAD` этого остатка на тех же отсчётах, и такие отсчёты идут подряд не короче 5. Это масштаб робастного остатка физической модели, не пространственный z-score детектора этапа 1.

Словарь:

| ключ | смысл |
|---|---|
| `active_frac` | доля активного времени |
| `period_s` | период, секунды. Локальный пик периодограммы (фундаментальная среди сильных гармоник). 0, если пика нет и это тренд. Если спектра нет, берётся медиана пауз между включениями |
| `duty` | скважность: медиана доли активного времени по целым циклам |
| `k` | 1/с, со знаком (отрицательный k — не пассивная релаксация) |
| `T_inf` | равновесие пассивной модели, в единицах ряда |
| `resid_mad` | MAD остатка `dT/dt` |
| `active_sign` | +1 нагрев, −1 охлаждение, 0 если активного участка нет |

В сеть эти числа входят как `FEATURE_NAMES`: доля, `log1p(период в минутах)`, скважность, `k` в 1/час, `T_inf`, MAD, знак. `stack_scalars(..., enabled=False)` возвращает тот же объект скаляров.

Ряд для зоны — среднее канала 0 кэша по интервалу дистанции зоны на всей записи, не только внутри бокса. Канал 0 — `dT/σ` (`dts/features.py`): сырое поле `T` из кэша снято `scripts/slim_train_cache.py`. В этих единицах `k` не зависит от деления на σ. На реальных CSV ряд — медиана профиля в °C.

Отдельного класса `HVAC_Cycle` в синтетике v8 нет. Правила haklolarp называют суточный цикл `Periodic_Thermal` и кладут его в `HVAC_Diurnal` (метка генератора `diurnal_section`). Ниже F1 Periodic_Thermal — это F1 `HVAC_Diurnal`. Число для `HVAC_Cycle` не подставляется.

## Нейросеть

Текущий этап 2 — EventNet (2D-CNN по кропу 32×64 и MLP по 19 скалярам) и LightGBM `full` (скаляры, 24 статистики кропа, форма, контекст соседей). Выпущенная смесь — 0.5/0.5 без температуры.

За флагом `use_runtime` скалярный вход EventNet длиннее на 7 признаков. `use_series` добавляет ещё 1D-свёртку по ряду длины 128 (z-score формы, не амплитуды); на старте её линейная голова имеет std 0.01, чтобы не перебить кроп. Оба флага по умолчанию выключены, `make_runtime_net(..., use_runtime=False)` повторяет логиты EventNet при тех же весах.

Протокол как у `scripts/train_stage2.py`: GroupKFold(5) по `seq_id` на `split != test` (1780 зон v8), 40 эпох, AdamW 2e-3, weight decay 1e-3, веса классов, label smoothing 0.05, отражение по x с вероятностью 0.5, на инференсе среднее с отражением. Нормировка скаляров и runtime-признаков считается только по обучающей части фолда. Test — модели, заново обученные на всём dev; в выбор флага не входит. Реальные `MGTS_data/1-6.csv` не используются ни для обучения, ни для калибровки, ни для выбора флага.

Критерий включения (только нейросеть, не LGBM): на GroupKFold macro-F1 не ниже парного EventNet больше чем на 0.001 и F1 `HVAC_Diurnal` выше больше чем на 0.001. Иначе флаг остаётся выключенным.

Опубликованный ориентир того же протокола при 40 эпохах (`artifacts/eval/stage2_v8.json`): EventNet macro-F1 0.904, F1 HVAC_Diurnal 0.981; LGBM full macro-F1 0.947; смесь 0.5/0.5 macro-F1 0.955.
