# MTL. Сегментация и гетероскедастичная амплитуда ΔT

Вспомогательная задача — регрессия подписанного ΔT события в градусах. Общий ствол — U-Net ширины 16 со старта `artifacts/stage1/unet_v810ft.pt`. Голова регрессии — свёртка 1×1 с последнего декодера `d1`, два канала: среднее μ и log σ² пикселя. `dts/models.py` не меняется: на выводе без флага `aux` модуль возвращает только логиты сегментации, и детектор считается как прежде, \(s=1-p(\text{фон})\).

Обучение только на синтетике v8 train. Реальные CSV, зоны и спектр кабеля не читаются. Порог по ним не ставится. Выпуск `models_release/` не перезаписывается.

## Потеря

Сегментация — уже принятая `focal+tversky_ce`.

Регрессия — гетероскедастичный гауссов NLL Кендалла и Гала (Kendall, Gal, NeurIPS 2017 / CVPR 2018). На пикселе события \(s_i=\log\sigma_i^2\):

\[
\mathrm{NLL}_i=\tfrac12 e^{-s_i}(y_i-\mu_i)^2+\tfrac12 s_i.
\]

\(L_{reg}\) — среднее NLL по пикселям события в батче. Фон и помеха в регрессию не входят: у них нет ΔT события. Цель \(y\) — поле `severity` из `data/synth_meta/v8/labels.csv`, со знаком (нагрев положительный, охлаждение отрицательный). По модулю оно совпадает с `amp_obs_C` (медианный зазор около 0.004 °C). Метки нужны только как цель потери и для отчёта IoU. Аугментация семплера (зеркало по x, множитель каналов) цель в градусах не масштабирует.

Веса задач — гомоскедастичная неопределённость той же работы. \(s_{seg}\) и \(s_{reg}\) — обучаемые \(\log\sigma^2\) задачи:

\[
L=e^{-s_{seg}}L_{seg}+\tfrac12 s_{seg}+e^{-s_{reg}}L_{reg}+\tfrac12 s_{reg}.
\]

Это запись \(L/\sigma^2+\log\sigma\). Множитель ½ гауссовой регрессии уже стоит внутри NLL, второй раз он не ставится. На старте \(s_{seg}=0\) (вес сегментации 1, градиент детектора как у обычного дообучения) и \(s_{reg}=2\) (вес регрессии \(e^{-2}\)). Смещение канала log σ² равно 2. Оба log σ² в потере обрезаются в \([-8,8]\), чтобы экспонента не переполнялась.

BatchNorm заморожен. AdamW, lr \(10^{-4}\), weight decay 0, клип градиента 1. Тайл 128×256, батч 8, до 8 эпох по 80 шагов, терпение 3. Потоки 2. Стена обучения 40 минут и не больше 45. Эпоха выбирается по proxy IoU при FAR \(10^{-3}\) на первых восьми последовательностях v8 val. Если ни одна эпоха не выше старта, остаются веса инициализации.

## Отбор

Рецепт заморожен, alpha на val не перебирается:

\[
\mathrm{ens\_blend}=0.5\cdot\mathrm{ens\_u2ft\_tcn\_lgbm}+0.5\cdot\mathrm{unet\_mtl}.
\]

Официальная цифра — пиксельный IoU при FAR \(10^{-3}\) на всём v8 val. Порог — квантиль фона `valid & ev==0 & nu==0`. Test v8, v10 и v11 считаются этим порогом и заново его не ставят.

Вложенная проверка — `scripts/s3_sel_core.py`, те же функции, что у `scripts/s3_sel2_cv.py`: `sequence_folds` (\(i \bmod k\), \(k=2\) и \(k=5\)), порог только по фону holdout, `micro_iou` по сумме tp/fp/fn. Карты полные. `nested_verdict` принимает метод, только если минимум из двух micro строго выше \(0.3867+0.003=0.3897\). Дополнительно прирост micro при \(k=5\) против победителя на тех же фолдах должен быть не меньше 0.003.

`beats=yes` только если одновременно:

- протокол воспроизвёл победителя (v8 val/test и v10/v11 test в пределах \(10^{-4}\));
- val смеси выше 0.38671235821914546 больше чем на \(10^{-4}\);
- вложенная проверка принята;
- test IoU на v10 и на v11 не хуже победителя.

Строка `BEATS_WINNER` не пишется. Слабый recall — доля событий \(\le 2^\circ\mathrm{C}\) с покрытием не меньше 30% пикселей.
