# Накопление свидетельств для слабых событий (≤2°C)

Скрипт `scripts/s3_accum.py`. Числа: `artifacts/eval/s3_accum_v8.json`, `s3_accum_v10.json`, `s3_accum_v11.json`.

Модели не обучались. `dts/postproc.py`, `dts/events.py`, `dts/models.py`, `models_release/` и скрипты оценки не менялись. Задача D (runtime HVAC) закрыта, флаг выключен; этот расчёт её не продолжает.

Вход — уже посчитанные вероятности ансамбля `ens_u2ft_tcn_lgbm` (`artifacts/pred/<ver>/ens_u2ft_tcn_lgbm/<split>/seq*.npz`, поле `s`). Преобразование видит только `s` и маску `valid`. Метки `ev` / `nu` и таблицы событий используются после порога, только чтобы посчитать FAR, IoU и recall.

## Преобразования

`logit(s) = log(p / (1-p))`, `p = clip(s, 1e-4, 1-1e-4)`.

Окна по времени — 3, 7 и 15 отсчётов. Шаг трассы 120 с, шаг по дистанции 0.25 м. Невалидные отсчёты и паддинг нулём в сумму не входят: числитель и знаменатель считаются одним и тем же `uniform_filter` (`mode=constant`, `cval=0`), наружу отдаётся отношение. При одинаковом числе valid в окне сумма и среднее монотонны, и порог FAR их не различает. Сумма лог-шансов оставлена отдельным вариантом: на краях маски длина окна плавает, и сумма с средним расходятся.

| имя | карта |
|---|---|
| `identity` | `s` |
| `ma_s_w3/7/15` | скользящее среднее `s` по времени |
| `logit_sum_w3/7/15` | сумма `logit(s)` по тому же окну |
| `cusum_fwd`, `cusum_fwd_d05` | Page CUSUM вперёд: `C_t = max(0, C_{t-1} + logit(s_t) - k)` |
| `cusum_ctr`, `cusum_ctr_d05` | `min(CUSUM вперёд, CUSUM назад)`, чтобы масса сидела внутри серии, а не на её хвосте |
| `box_t*_x*` | среднее `logit(s)` в прямоугольнике время×дистанция: 3×3, 7×3, 7×9, 15×3, 15×9, 5×21 |

Опорный уровень CUSUM — медиана `logit(s)` по столбцу дистанции, только по `valid`. Это не метка и не пространственный z-score. `d05` добавляет к медиане drift 0.5 в единицах логита: копится только избыток над типичным фоном столбца. Невалидный отсчёт состояние не сдвигает.

## Порог и метрики

Порог каждого варианта — квантиль фона v8 val при FAR 1e-3. Фон: `valid & ev==0 & nu==0`. Формула та же, что `dts.metrics.far_threshold` (сортировка, `+1e-12`). На test v8, v10 и v11 порог не переоценивается: у v10 и v11 нет val-предсказаний этого ансамбля.

Пиксельный IoU — `dts.metrics.confusion` / `prf`, истина `ev>0`, предсказание `score >= thr` и `valid`. Событие засчитано, если предсказано не меньше 30% его пикселей (как `scripts/eval_stage1.py`). Weak recall — доля таких попаданий среди событий с `amp_obs_C ≤ 2` (`by_amp["<=2C"].recall`). Рядом пишется pixel recall: сумма угаданных пикселей этих событий к их площади.

Выбор только по v8 val. Вариант принимается, если val IoU ≥ 0.387, либо weak recall строго выше identity при val IoU ≥ 0.38. Среди прошедших берётся больший weak recall, затем IoU, затем F1. Test в выбор не входит.

Контроль протокола: identity обязан повторить опубликованный val IoU 0.386712 и порог 0.8608087301264272 (`artifacts/eval/r7_ens_u2ft_tcn_lgbm.json`).

## Результаты

Протокол сошёлся с опубликованным identity: val IoU 0.386712, порог 0.8608087301264272, test IoU 0.405276, test weak recall 0.017544 (1 из 57). Дельты нулевые. На val слабых событий с ненулевой маской 28, попаданий 0, pixel recall 0.00137.

Принят один вариант: `box_t3_x3` (среднее логита в окне 3×3). Val IoU 0.387119 ≥ 0.387, порог на фоне val 1.8026 в единицах логита. Weak recall при этом не вырос: val 0/28, test 1/57 — те же 0.017544, что у identity. Pixel recall слабых чуть ниже (val 0.00102 против 0.00137, test 0.01238 против 0.01273). Прирост val IoU +0.00041 сидит в пикселях сильных событий: recall `2-5C` и `>5C` те же 0.405 и 0.802, pixel recall `>5C` 0.6355 → 0.6380.

Test в выбор не входил. Там IoU `box_t3_x3` ниже identity: v8 0.404643 против 0.405276, v10 0.403277 против 0.403898, v11 0.403271 против 0.403900. FAR на v8 test остаётся 0.00232. Weak recall v10 и v11 — 0 из 60 и у identity, и у бокса. В `dts/postproc.py` вариант не включался.

Единственный рост weak recall даёт центрированный CUSUM с drift 0.5 (`cusum_ctr_d05`): val 1/28 = 0.0357, v8 test 2/57 = 0.0351, v10 и v11 2/60 = 0.0333. Val IoU при этом 0.1799, ниже пола 0.38, поэтому вариант не принят. Прямой CUSUM копит массу к концу серии и на FAR 1e-3 оставляет val IoU около 0.03. Скользящее среднее `s` и сумма логитов по 3–15 отсчётам weak recall не поднимают и монотонно снижают val IoU с длиной окна.
