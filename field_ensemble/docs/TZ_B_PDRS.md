# Задача B. PDRS на вероятностной карте ансамбля

Нейросетевой вариант извлечения зон. Поле — вероятность `s` ансамбля `ens_u2ft_tcn_lgbm` (U-Net w24, U-Net v8+v10, TCN, пиксельный LightGBM), полярность — знак канала `h`. Это не z-статистика. Код: `dts/pdrs.py` (`extract_zones_pdrs`). Опорный метод — порог и связные компоненты, `extract_zones_cc`, порог far 1e-3 выпуска `0.86080873` (`models_release/stage1_thresholds.json`). Порог на этих прогонах не пересчитывался.

Реальные файлы `/workspace/mgts/MGTS_data/1-6.csv` и карточки оператора в обучение и в подбор параметров не входят. Меток на реальных данных нет, и они здесь не назначаются.

## Алгоритм

Семена — локальные максимумы `s` не ниже `seed`, внутри маски `s ≥ floor` и валидных клеток. Фронты растут вместе: watershed по `-s`, 4-соседство. Разрыв времени больше `max_gap_s` (300 с) фронт не перепрыгивает. Соседние области сливаются, если седло на их границе выше `r_saddle · min(пиков)`. Зона с медианой `s` ниже `region_median` или короче `min_cells` отбрасывается. Полярность зоны — знак среднего `h`.

Сетка только на v8 val, 45 записей: `seed` {0.86, 0.95}, `floor` {0.3, 0.5, 0.7}, `r_saddle` {0.3, 0.6, 0.9}, `region_median` {0.5, 0.7}. Критерий сетки — максимум пиксельного IoU по всем событиям (`iou_all`). Шесть точек с `seed=0.95`, `floor=0.7` дают один и тот же val `iou_all` 0.3888. Скрипт берёт первую из них. У `r_saddle=0.9` при том же IoU ниже точность зон (0.7458 против 0.8255), поэтому оставшаяся точка не хуже соседей по сетке.

Выбранные параметры, заморожены для v8/v10/v11 test и для реальных файлов: `seed=0.95`, `floor=0.7`, `r_saddle=0.3`, `region_median=0.5`. Файл `artifacts/eval/pdrs_best_params.json`.

## Как считаются столбцы

Пиксельный IoU: TP / (TP + FP + FN) по валидным клеткам. Hot — классы генератора 1–4, cold — 5–6, предсказанная полярность — из `h`. Event recall — доля связных компонент истинной маски (8-соседство), которых касается хотя бы одна зона. Zone precision — доля зон, которые пересекают истинную компоненту. Зон/сутки — число зон, делённое на длительность записи. Ошибка границ — медиана по сопоставленным зонам: среднее абсолютное отклонение двух краёв рамки, шаг сетки 120 с и 0.25 м. Время — секунды на запись, только извлечение зон.

## Гибрид: recall CC и границы PDRS

Цель — не потерять event recall порога (на v8 test у CC он 0.6088) и сдвинуть точность зон и ошибку рамки к PDRS. Две семьи, обе в `extract_zones_hybrid`:

- `seed` — тот же PDRS, семя равно порогу far 1e-3 `0.86080873` (рост до `floor`). Отдельно две точки с семенем 0.95 и полом на том же пороге.
- `refine` — носитель зоны это CC при far 1e-3, внутри него PDRS пересобирает сегмент. `fallback=True` возвращает компоненту CC, в которой PDRS ничего не оставил.

Сетка 28 точек только на v8 val, 45 записей. Опорные CC и PDRS посчитаны тем же скорером. Правило выбора, до test: recall не ниже CC. Среди таких точек максимум средней доли пути от CC к опорному PDRS по трём осям: zone precision, ошибка границы по времени, ошибка границы по расстоянию. Дальше iou_all и recall. Опорный PDRS — уже замороженная точка `seed=0.95`, `floor=0.7`, не подбирался заново.

`refine` в отбор не вошёл. С запасным CC recall либо чуть ниже планки (0.6359 при ядре 0.95), либо рамка раздувается (до 1620 с / 3.88 м). Без запасного recall падает до 0.5485.

Четыре точки `seed=порог`, `floor=0.7`, `r_saddle` 0.3 или 0.6, `region_median` 0.5 или 0.7 дали на val одни и те же метрики. Берётся первая: `r_saddle=0.3`, `region_median=0.5`. Файл `artifacts/eval/pdrs_hybrid_best_params.json`. Сводный счёт 0.6541.
