# Миграции ClickHouse

Пуш в ветку `data` обновляет уже работающий проект `haklolarp-stack`
(`/opt/haklolarp-stack`), а не поднимает второй ClickHouse.

Файлы `*.sql` из этого каталога применяются **автоматически один раз** при
деплое — одноразовым сервисом `migrate` (`stack/compose.yaml`). Учёт
применённых — в таблице
`haklolarp.schema_migrations`. Так в живую базу попадает новая схема.
`stack/clickhouse/init.sql` на существующем томе повторно не выполняется.

## Правила

- Порядок задаёт имя файла: `0001-имя.sql`, `0002-имя.sql`, ... (лексикографически).
- Каждый файл применяется ровно один раз. Менять уже применённый файл нельзя —
  добавь новый.
- Первичная схема стенда (`profiles_raw`, `events`, `models_registry`) — в
  `stack/clickhouse/init.sql`; он выполняется ClickHouse только при первой
  инициализации тома `ch-data`.
- Применить вручную (ad-hoc, без деплоя) — см. `stack/DATA_GUIDE.md`.
