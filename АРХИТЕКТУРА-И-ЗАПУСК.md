# Архитектура и запуск

Снимок ветки `ml` репозитория haklolarp, коммит `71fc4eb` от 16 октября 2026. В этот репозиторий вошли все папки той ветки. В `main` haklolarp они не вливались.

Данные кейса — шесть файлов температуры вдоль оптического волокна в помещении, `1.csv`–`6.csv`. В git их нет: файлы кладут рядом с кодом, обычно в каталог `MGTS_data`. Значение `−300` — пропуск измерения, не температура. Имя причины («насос», «протечка», «пожар») из одной температуры не выводится. Метки в коде — гипотеза по форме пятна.

На ветке три разных контура. Их нельзя смешивать.

1. `fiber/` и `scripts/` — рабочая обработка ветки. Очистка `median_x3`, кандидат зоны `spatial_z_halo`. Нейросети этот статус не сменили.
2. `grok_solution/` — отдельный исследовательский контур «поле как картинка». Выпущенный по их протоколу ансамбль называется `ens_u2ft_tcn_lgbm`. Цифры IoU и F1 ниже относятся только к этому протоколу на синтетике и карточках, не к жюри.
3. `solutions/larpathon/` — короткий прототип ансамбля статистики и патч-автоэнкодера. У него свои тесты и один вес `weights/synth_patch_net.pt`.

## 1. Рабочий контур `fiber`

Команды из корня репозитория. Нужен Python 3.11 или новее. На машине с RTX 4080 SUPER для обучения стоит Python 3.13 и CUDA. Тесты и шаги без обучения видеокарты не требуют.

```powershell
python -m pip install -e ".[dev]"
python scripts/transform_csv.py --raw-root MGTS_data --out-root artifacts/records
python scripts/denoise_records.py
python scripts/detect_anomalies.py
python scripts/plot_anomaly.py
python scripts/classify_zones.py
python -m pytest tests -q
```

После первого шага у каждой записи появляются `raw_c.npy`, `valid.npy`, `x_m.npy`, `time_s.npy`, `meta.json`. Индекс шести файлов — `artifacts/records/index.json`. Каталог `artifacts/` создаётся прогоном.

Один файл и два метода очистки:

```powershell
python scripts/denoise_records.py --only 5 --methods median_x3 wavelet_x
python scripts/score_denoise.py
```

По умолчанию денойз считает `median_x3`, `median_xt`, `savgol_x`, `bilateral_x`, `wavelet_x`, `tv_x`. Решение «норма / кандидат зоны» на рабочем контуре ставит spatial Z по полю `median_x3`. Форма зоны подписывается отдельно и причину не называет.

API:

```powershell
python -m pip install -e ".[api]"
python -m uvicorn fiber.api:app --host 127.0.0.1 --port 8082
```

Живые адреса: `GET /health`, `GET /methods`, `POST /denoise/profile`.

Обучение пишет веса в `models/weights/` и нужно только на GPU. Скан сырой трассы этими весами запускается, только если отчёт выбора назвал именно эту модель. На измеренных прогонах рабочий статус остался у `spatial_z_halo`.

```powershell
python -m pip install -e ".[train]"
python scripts/train_conv_ae.py --device cuda
python scripts/score_ae.py
python scripts/train_conv1d_n2self.py --device cuda --epochs 8
python scripts/train_unet2d_denoise.py --device cuda --epochs 6 --crops 4000
python scripts/train_patch_classifier.py --device cuda --epochs 16
```

Применить уже обученный файл 1D-сети к записи 5:

```powershell
python -c "from pathlib import Path; from fiber.io import Record; from fiber.denoise import apply_method; r=Record.load(Path('artifacts/records/5')); d=apply_method('conv1d_n2self', r.raw_c, r.valid, weights=Path('models/weights/conv1d_n2self.pt')); print(d.shape)"
```

Остальные команды обучения и правило свидетелей — в `docs/PIPELINE.md` и `models/weights/README.md`. Логистические модели контекста пишут вес только если witness pass count строго выше 7/8. На записанных прогонах этот порог не был пройден, опубликованной классификацией остаётся прежний детектор.

Код сетей рабочего контура:

| Файл | Сеть |
| --- | --- |
| `fiber/models/conv1d_denoise.py` | 1D CNN, Noise2Self |
| `fiber/models/unet2d_denoise.py` | 2D U-Net очистки |
| `fiber/models/conv_ae.py` | свёрточный автоэнкодер |
| `fiber/models/patch_classifier.py` | классификатор кропа |
| `fiber/models/residual_net.py` | остаточная CNN |
| `fiber/models/column_graph.py` | граф колонок |
| `fiber/models/column_transformer.py` | трансформер колонок |
| `fiber/models/depth_cnn.py`, `blindspot_x.py`, `n2n_tsr.py`, `zsn2n.py`, `summary_nets.py` | соседние исследовательские архитектуры того же контура |

`ml_common/` подключается как общий слой событий. Адаптеры: `ml_common/adapters/fiber.py`, `grok_gen2.py`, `larpathon.py`.

## 2. `grok_solution`

Это самодостаточный пакет внутри ветки. Рабочий каталог — `grok_solution/`, не корень репозитория. Зависимости свои.

```powershell
cd grok_solution
python -m pip install -r requirements.txt
python -m pytest tests -q
```

В `requirements.txt`: NumPy, SciPy, pandas, Matplotlib, scikit-learn, LightGBM, joblib, h5py, PyTorch. Для машины без CUDA в том же файле указан индекс CPU-сборки torch. OpenCV не обязателен: он в `requirements-cv.txt` и импортируется лениво.

Полный прогон на CPU описан в `scripts/run_all.sh`. Ему нужны синтетический корень `SYNTH` и папка реальных CSV `REAL`. Этих данных в git нет.

```bash
cd grok_solution
SYNTH=/path/to/synth_v8/d REAL=/path/to/MGTS_data bash scripts/run_all.sh
```

Скрипт по порядку строит кэш, учит stage 1 (`unet`, `tcn`, `dilated`), считает matched filter и pixel LGBM, оценивает stage 1, учит stage 2, собирает релиз, гоняет реальные CSV и пишет отчёт. Повтор с места остановки — `scripts/run_resumable.sh`.

Отдельные входы, если кэш уже собран:

```powershell
python scripts/predict.py --method unet --cache artifacts/cache/v8
python scripts/eval_stage1.py --cache artifacts/cache/v8 --labels $SYNTH/labels.csv --sequences $SYNTH/sequences.csv
python scripts/run_real.py --real-root $REAL
python scripts/make_report.py
```

Что лежит в пакете:

| Папка | Зачем |
| --- | --- |
| `dts/` | Код моделей и инференса: U-Net, TCN, gen2/gen3, static-net, MAE, CV-зоны, аугментации. Тревога в `dts/infer.py` не поднимается для классов суточного хода и артефакта датчика. |
| `scripts/` | Обучение, предсказание, отчёты, серия опытов `s3_*`. |
| `tests/` | 34 файла проверок пакета, без шести CSV. |
| `experiments/` | Короткие опыты: `cv`, `dilated`, `matched_filter`, `multiscale`, `realnet`, `ssl`, `unet_ms`, `unsup`. |
| `docs/` | Записка `NOTE.md`, таблицы `RESULTS.md`, решение о релизе `RELEASE_DECISION.md`, журналы сессий `S3_*.md` и `STATE.md` в корне пакета. |
| `models_release`, `models_release_dom`, `models_release_gen2`, `models_release_mae`, `models_backup` | Слоты выпущенных весов. Крупные чекпоинты обучение кладёт в `artifacts/`, этот каталог прогоном создаётся на машине и в git как набор гигабайтных весов не хранится. |

По журналу `STATE.md` на 15 октября 2026 выпущенным по их валидации остаётся ансамбль `ens_u2ft_tcn_lgbm`: U-Net ширины 24, дообученный U-Net, TCN и пиксельный LightGBM. Там же записаны val IoU около 0.387 и test IoU около 0.405 на их синтетическом протоколе. Это не замена `spatial_z_halo` в `fiber/` и не внешняя приёмка.

Читать в таком порядке: `grok_solution/docs/NOTE.md`, затем `docs/RESULTS.md` и `docs/RELEASE_DECISION.md`. Оглавление опытов — файлы `docs/S3_*.md` и `docs/EXPERIMENTS_S2.md`.

## 3. `solutions/larpathon` и его тесты

Прототип читает один CSV или папку CSV. Фон снимается медианой, локальный остаток ищет статистика, патч-автоэнкодер доучивается на этом файле. Разметки событий у прототипа нет. Имена пятен — правила формы.

Зависимости и тесты, из корня репозитория:

```powershell
python -m pip install -r solutions/larpathon/requirements.txt
python -m pytest solutions/larpathon/tests -q
```

Тесты: `tests/test_pipeline.py` и `tests/test_train_synth.py`. Они не требуют шести боевых CSV.

Прогон одного файла, только статистическая ветка, без автоэнкодера:

```powershell
python solutions/larpathon/main.py path\to\file.csv --no-ae --device cpu
```

С автоэнкодером на CPU, шесть эпох, порог по перцентилю 99.2:

```powershell
python solutions/larpathon/main.py path\to\MGTS_data --epochs 6 --device cpu --plot-dir solutions\larpathon\reports\run
```

Полезные флаги `main.py`: `path` (файл или папка), `--max-rows`, `--seed`, `--percentile`, `--epochs`, `--plot-path`, `--plot-dir`, `--no-ae`, `--device cpu|cuda`.

Синтетический вес, который уже лежит в git:

```powershell
python solutions/larpathon/train_synth.py
```

Файл веса — `solutions/larpathon/weights/synth_patch_net.pt`. Пояснение прототипа — `solutions/larpathon/NOTE.md`. Готовые картинки прошлых прогонов — `solutions/larpathon/reports/`.

Тот же прототип продублирован историей ветки `ml_test2_larpathon`. В этот снимок он входит как папка `solutions/larpathon`, отдельным деревом его копировать не нужно.

## 6. Веб и стенд, если они нужны отдельно

К письму с кодом обработки они не обязательны. Веб из этой ветки собирается из `apps/web` и `services/web-api`. Стенд данных описан в `stack/README.md` и `stack/FOR_ML.md`. Поднимать его, чтобы прогнать `fiber` или larpathon, не нужно.

## Чего в снимке нет

- Шести исходных CSV и любого каталога `artifacts/`, пока его не создал локальный прогон.
- Крупных чекпоинтов `models/weights/*.pt` и обучающих кэшей `grok_solution/artifacts/`.
- Секретов, паролей стенда и ключей доступа.
