# Прогон основного ансамбля на большем объёме

Тот же пайплайн, что в `main.py`: CNN-автоэнкодер 6 эпох плюс статистический residual, порог 99.2. Считалось на RTX 4080 SUPER. Синтетические метки только для подсчёта попаданий, порог по ним не подбирался.

Синтетика: 10 тестовых записей короче 400 трасс (`dts_synth_v1`, split test). В загруженном окне 98 событий. Рамка детектора пересекла 23 из них.

| метка | попадания |
|---|---|
| section_heating | 11/14 |
| cooling | 2/3 |
| coldspot | 3/6 |
| slow_warming | 3/7 |
| hotspot | 3/16 |
| tracing | 1/52 |

Лишних рамок, которые не попали ни в событие, ни в помеху: 119. Ещё 33 попали только в помеху (суточный ход, скачок всей трассы, ступень коннектора). Трассировку, которая шагает вдоль кабеля, ансамбль почти не собирает в одну рамку.

Реальные файлы целиком, без обрезки в 300 строк:

- `4.csv` 708×1716, 18 событий. Два самых длинных нагрева: 105–114 м, 536 мин, 9.25 м, +6.85 °C и 92–100 м, 286 мин, 8.0 м, +4.76 °C. Это та же зона, что и на срезе из 300 строк, но цифры другие: другой кусок записи меняет среднюю температуру и порог.
- `3.csv` 788×1714, 38 событий. Нагрев 372–381 м, 212 мин, +6.45 °C и 62–66 м, 484 мин, +1.81 °C.
- `2.csv` 696×2349, 42 события. Нагревы около 104–108 м и пачка узких рамок около 468–473 м.

Картинки: `seq*.png` и `real_2.csv.png`, `real_3.csv.png`, `real_4.csv.png`. Файлы 1, 5 и 6 в этот прогон не входили: они длиннее и гуще по точкам.
