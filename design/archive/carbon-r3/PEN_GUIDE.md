# Pen: установка и работа с R3

Актуально на 9 октября 2026. Общий проект содержит 76 корней: 53 новых макета R3, 19 экранов R2 и четыре исходных корня Захара. Доказательства проверки файлов — в [QA.md](QA.md) и [pen/validation.json](pen/validation.json).

## Получить проект

```sh
git clone --branch web --single-branch https://github.com/werd0y45/haklolarp.git
cd haklolarp
```

Если checkout уже существует, сохраните работу, перейдите на ветку `web` и выполните `git pull --ff-only`. Альтернатива — выбрать ветку `web` на GitHub и скачать Code → Download ZIP. Для закрытого репозитория нужен доступ.

| Файл | Назначение |
|---|---|
| [pen/dts-workbench.pen](pen/dts-workbench.pen) | Весь актуальный проект; основной источник дизайна |
| [pen/screens/](pen/screens/) | 53 независимых снимка новых экранов для отдельных правок |
| [SCREEN_INDEX.md](SCREEN_INDEX.md) | Названия, роли, PNG и Pen каждого нового экрана |
| [../carbon-r2/pen/archive/](../carbon-r2/pen/archive/) | Исторический черновик, не образец актуального стиля |
| [PRODUCT_SPEC.md](PRODUCT_SPEC.md), [MOBILE_UX.md](MOBILE_UX.md) | Поведение, права и мобильные критерии |

PNG — просмотр; Pen — слои текста, форм, таблиц и векторных графиков. Изменение отдельного файла не синхронизируется с общим автоматически.

## Установка для участника

Скачайте приложение с [официальной страницы Pen](https://www.pen.dev/downloads). На Windows запустите установщик; на macOS перенесите приложение из DMG в Applications; на Linux выберите подходящий AppImage/tarball. Откройте `design/carbon-r3/pen/dts-workbench.pen` в приложении. См. [Installation](https://docs.pen.dev/getting-started/installation).

Альтернатива — расширение **pen.dev** в VS Code/Cursor. Если файл показан текстом, проверьте расширение и включите `pen.dev: Toggle Design Mode`; содержимое .pen вручную не редактировать.

Используются IBM Plex Sans и IBM Plex Mono, включая кириллицу. При подмене шрифта и смещении подписей установите семейства из [официального IBM Plex](https://github.com/IBM/plex), затем переоткройте документ. Шрифты не включены в Git.

## Правка вручную

1. Создайте отдельную Git-ветку и откройте общий проект либо, например, `pen/screens/m-signal.pen`.
2. Найдите экран по названию и индексу. Не редактируйте исходные экраны Захара вместо Carbon.
3. Выберите текстовый слой и измените текст; форму/график — через её отдельные слои и свойства. PNG не превращается в редактируемый экран.
4. Проверьте переносы, границы, единицы измерения, шкалу и мобильные кнопки. Не меняйте измерения как декоративную картинку.
5. Сохраните .pen. Выделите корень экрана, экспортируйте PNG 2x через Export layer. Откройте полученный PNG для проверки; инструкция — [Import & Export](https://docs.pen.dev/core-concepts/import-and-export).
6. Если правили одиночный файл, перенесите согласованную правку в общий документ через Pen, сохраните и переэкспортируйте.

Исходные CSV не нужны для обычной правки текста и композиции. Для пересчёта графиков нужны реальные данные; Pen здесь не вычисляет новый научный сигнал.

## Подключить внешнего агента

Запустите Pen, откройте нужный документ, включите интеграцию своего клиента в Settings → MCP и перезапустите клиент. Проверьте сервер `pencil`. В версии Pen автора для Codex интеграция называется Codex CLI; поддерживаемые клиенты зависят от версии. Официальные инструкции: [AI Integration](https://docs.pen.dev/getting-started/ai-integration), [Installation](https://docs.pen.dev/getting-started/installation).

Агенту передайте абсолютный путь на **своей** машине. Пути автора `C:/dev/mgts/...` не переносимы. Изображение в чате не предоставляет агенту доступ к слоям Pen.

Готовый стартовый промпт:

```text
Работаем над DTS Workbench в ветке web.
Прочитай design/carbon-r3/AGENTS.md, README.md, PRODUCT_SPEC.md,
MOBILE_UX.md, PEN_GUIDE.md, STYLE.md и manifest.json.
Pen: <абсолютный путь к design/carbon-r3/pen/dts-workbench.pen>.
Задача: <экран и конкретное изменение>.

Через pencil прочитай read_skill(), pen-schema.md и execute.md.
Проверь get_app_state() и активный документ. Найди экран через Get.
Не читай/редактируй .pen как текст или JSON. Сохраняй отдельные слои.
Сохраняй Carbon, IBM Plex, dts.* и научную семантику графиков.
Не придумывай измерения, человеческие ответы или оценки точности.

После правки отдельным вызовом проверь проблемы границ, визуально проверь
TakeScreenshot/PNG, сохрани Pen и экспортируй экран PNG 2x.
Обнови индексы. Сообщи, какие файлы изменены и что проверено.
```

## CLI для точной правки и экспорта

Для ручной работы CLI не нужен. Для терминального режима требуется Node.js 22.19+. Установите CLI и авторизуйтесь:

```sh
npm install -g @pen.dev/cli
pen version
pen login
```

В этой поставке использован CLI 0.3.10. При другой версии сначала проверьте `pen interactive --help` и [официальный reference](https://docs.pen.dev/for-developers/pen-cli).

Подключение к открытому приложению:

```sh
pen interactive -a desktop -i design/carbon-r3/pen/dts-workbench.pen
```

Дальше команды **внутри Pen shell**:

```javascript
read_skill()
read_skill({path:"pen-schema.md"})
read_skill({path:"execute.md"})
get_app_state()
execute({input:'Print(Get("q3pOto", {depth:1}));'})
execute({input:'TakeScreenshot(["q3pOto"]);'})
execute({input:'Export(["q3pOto"], "png", "./export-local", {scale:2});'})
save()
exit()
```

`q3pOto` — корень мобильного сигнала в текущем индексе. Перед правкой проверьте ID и активный документ. App-режим работает с открытым canvas; не считайте, что параметр пути автоматически переключил документ. В app-режиме `save()` сохраняет активный файл, `--out` не является надёжным способом создания другой копии.

Для отдельного вывода используйте headless:

```sh
pen interactive -i design/carbon-r3/pen/screens/m-signal.pen -o m-signal-my-edit.pen
```

Прочитайте инструкции, измените слои через `execute`, выполните `save()` и `exit()`. Проверьте наличие выходного .pen и откройте его заново. Если execute возвращает `editId`, исправляйте через `edits`, не повторяйте тот же ошибочный блок.

Desktop/headless могут растеризовать текст по-разному. Эталонные PNG R3 экспортированы из desktop; проверки структуры не гарантируют совпадение каждого пикселя. При заметной разнице проверьте шрифты и установку.

## Сохранение и Git

Перед переключением ветки/pull сохраните и закройте документ. Конфликт Pen не объединяйте как текст: сохраните обе версии и перенесите нужные слои средствами Pen. Изменившиеся ID/имена требуют обновления manifest и индекса.

Перед коммитом: общий Pen сохранён; отдельные снимки согласованы; PNG актуальны; ссылки работают; видео, секретов и локальных сессий нет. Для документальной поставки в `web` применяется `[skip ci]`, поскольку обычный push этой ветки запускает staging workflow. Изменение кода и его проверок — отдельная работа.
