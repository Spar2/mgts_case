# Работа с телефона

## Что меняется

Телефон — полноценный клиент назначенной работы. Основной путь оптимизирован для эксперта, чтение данных и наблюдение за запуском доступны сразу. Координатор и администратор открывают расширенные формы через меню; для них нарисованы мобильные настройки пакета и изменение прав. Не требуется переключаться на «десктопную версию сайта».

Не уменьшаем всю настольную таблицу. Очередь и записи превращаются в списки: название, источник/границы, состояние и явное действие. Дополнительные поля раскрываются в карточке ресурса. Фильтры открываются отдельным листом и возвращают в тот же список. Действия, которые на desktop можно показывать по hover, на touch видимы постоянно — это соответствует [рекомендациям Carbon Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines).

## Путь эксперта

1. Вход → доступный проект → моя очередь. Возвращение сохраняет фильтр и позицию списка.
2. Исходный сигнал → при необходимости полноэкранное поле/точный срез. Виден источник, диапазон, время и шкала °C.
3. Собственный ответ: событие / нет события / неоднозначно / недостаточно данных. Большие строки выбора, без случайной публикации при касании варианта.
4. Обоснование → сохранение. Обязательные поля не скрыты ниже клавиатуры; данные не теряются при ошибке.
5. После подтверждения сервера: следующий участок, история ответа или исправление новой ревизией. «Сохранено» не показывается после одного лишь локального сохранения.

Слепой режим скрывает результаты методов до самостоятельного суждения. Статические примеры выбранного ответа и обоснования помечены как примеры, реальных human labels не созданы.

## Графики без точного жеста

Поле температуры отделено от прокрутки страницы. На основной карточке жест не должен случайно менять область. Развернуть график — явная кнопка. Альбомный экран показывает поле и поля времени/координаты рядом; портретный — график, затем управление одним потоком.

Кнопки предыдущего/следующего профиля и числовой ввод дополняют drag/pinch. Это реализует принцип доступной альтернативы перетаскиванию из [WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements). Шаг по времени — по фактическим наблюдениям, не выдуманный равномерный ряд. Поле времени валидируется относительно записи; координата привязана к реальной оси.

Выбранный срез можно прочесть числовым списком/таблицей без цвета. При реализации этот режим обязателен, даже если макет показывает только кнопку/контракт. Нет зависимых от hover tooltip. Пропуск отличается текстом/маской/штриховкой, а не только цветом.

На мобильном preview использованы те же реальные агрегаты `5.csv / 270–330 м` и пространственный срез 17:20:22. Поле содержит медианы блоков 28×61, не каждую native-ячейку. Шкала 17.67–26.91 °C показана явно. При сравнении методов нельзя незаметно менять шкалу.

## Размеры, навигация и клавиатура

Дизайн выбирает 48 CSS px для основных кнопок и 56 px для строк выбора, с промежутками от 8 px. Это продуктовый выбор, а не утверждение, что WCAG требует 48: [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) задаёт 24 CSS px либо допустимые исключения/расстояния.

Главный mobile header — меню и аккаунт с областью касания минимум 48×48; сами иконки 24×24. Кнопка не должна иметь только 24 px hit area. В Pen отрисован визуальный размер иконок; hit area — контракт реализации. На узком экране 320 px сохраняются отдельные строки ответа и читаемый основной action.

Обычные страницы имеют один вертикальный поток. У длинной формы нижняя панель резервирует место в контенте и учитывает safe area. При клавиатуре панель поднимается или становится частью прокрутки; поле и его ошибка не перекрываются. Макет `m-keyboard` показывает уменьшенную рабочую область и схематическую клавиатуру, не снимок реального браузера. Это следует принципу [Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).

Back восстанавливает очередь и положение. Смена проекта предупреждает о неотправленном черновике. Меню показывает только разрешённые разделы и текущую роль. Все значимые действия доступны без свайпа, hover и горизонтального скролла всей страницы.

## Адаптация по доступной ширине

| Доступная ширина | Компоновка | Управление |
|---|---|---|
| 320–767 CSS px | Один поток, компактные списки, проверка в три шага | Меню кнопкой, инспектор отдельным листом, touch actions |
| 768–1199 CSS px | График широким блоком, срезы по вкладкам | Скрываемая навигация; параметры отдельно, без сжатия осей |
| 1200+ CSS px | Боковая навигация, поле + инспектор, два связанных среза | Таблицы/пакетные действия, видимые альтернативы hotkeys |
| Альбомный телефон | Поле + точный выбор, явное закрытие | Не навязывать ориентацию устройства |

Это проектные breakpoint, не требование Carbon. При увеличении текста используем доступную CSS-ширину, а не модель устройства. [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) допускает исключение для действительно двумерного контента; оно не оправдывает горизонтальную прокрутку форм и меню. У графика остаются альтернативные числовые данные и controls.

## Связь, черновики и безопасность

При разрыве связи показываем «не отправлено», а не «сохранён ответ». Локальный черновик разрешён только политикой проекта и с явным выбором доверенного устройства. Не скачиваем весь CSV в кэш телефона. Продолжение по кэшу не гарантируется и зависит от реально реализованной политики.

Перед отправкой восстановленного черновика сервер проверяет аккаунт, membership, назначение и revision. Конфликт открывает сравнение, не затирает ни сторону сервера, ни локальный текст. После отзыва доступа уже сохранённый локальный текст невозможно гарантированно удалить удалённо; возможность локального хранения должна быть согласована заранее.

Вход поддерживает password manager, вставку и автозаполнение. Второй фактор — одно поле кода с альтернативным настроенным способом, не головоломка и не шесть обязательных ручных вводов. Основание: [WCAG Accessible Authentication](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum).

## Приёмка реализованного интерфейса

- Проверить реальные браузеры Android и iOS: 320/390/430 px, планшет 1024, обе ориентации, увеличенный текст и zoom. Макеты — только визуальные контрольные точки.
- Пройти очередь → сигнал → точный срез → ответ → обоснование → подтверждение; повторить Back/обновление/смену проекта на каждом шаге.
- Открыть клавиатуру, ошибки длинной формы, меню и фильтры. Проверить фокус, safe area, отсутствие перекрытий и вложенной неудобной прокрутки.
- Проверить touch targets фактических DOM-элементов, порядок Tab, screen reader labels, состояния radio/disabled, announcements сохранения/ошибки, reduced motion.
- Прервать сеть во время отправки; повторить запрос; изменить revision в другой вкладке; отозвать membership. Ни дубля, ни молчаливой потери текста, ни ложного «сохранено».
- Сравнить точные данные с raw и шкалу с desktop. Обязательная доступная числовая альтернатива — часть реализации, не optional tooltip.

Только после этих проверок можно утверждать, что мобильный UX работает. Отсутствие обрезания в Pen не равно соответствию WCAG или тестированию на телефоне.
