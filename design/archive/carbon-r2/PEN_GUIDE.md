# Pen: установка, редактирование и работа с агентами

Инструкция для участников команды. Проверено 7 октября 2026: общий проект открывается в Pen, история светлая. Для сохранения использовался CLI `@pen.dev/cli` 0.3.9, для повторного открытия и сверки структуры — 0.3.10; при установке берите актуальную версию и сверяйте команды через `pen --help`.

## 1. Что скачать и какой файл открыть

Получите ветку `web`:

```sh
git clone --branch web --single-branch https://github.com/werd0y45/haklolarp.git
cd haklolarp
```

Если репозиторий уже есть, сначала сохраните свою работу, затем переключитесь на `web` и выполните `git pull --ff-only`. Для закрытого репозитория нужен доступ к GitHub. Без Git можно выбрать ветку `web` на сайте и скачать её через Code → Download ZIP.

| Файл | Когда использовать |
|---|---|
| [pen/dts-workbench.pen](pen/dts-workbench.pen) | Основной проект: все 19 новых экранов и досок, три оригинала Захара и исходные кнопки |
| [pen/screens/](pen/screens/) | Отдельные редактируемые экраны с теми же номерами и именами, что у PNG; удобно начать с одного |
| [pen/screens.json](pen/screens.json) | Индекс отдельных файлов и идентификаторов корневых слоёв |
| [pen/archive/zakhar-workspace-v0-exploratory.pen](pen/archive/zakhar-workspace-v0-exploratory.pen) | Неактуальный первый черновик, оставлен для истории; не брать за образец стиля |
| [STYLE.md](STYLE.md) | Актуальный стиль Carbon R2 и правила графиков |

PNG — картинки для просмотра. `.pen` — редактируемые документы со слоями текста, полей, таблиц и векторных графиков. Это не PNG, вставленные на холст. В актуальном общем проекте проверено отсутствие ссылок на внешние изображения и компоненты; сырые CSV не нужны, чтобы открыть и править макеты. Для научного пересчёта графиков нужны реальные данные проекта.

**Основной источник дизайна — `pen/dts-workbench.pen`.** Отдельные файлы — снимки соответствующих экранов. Изменения в них не появляются в общем проекте автоматически. После согласования перенесите правку в общий документ средствами Pen и обновите PNG. Архив V0 не синхронизируется.

## 2. Установка для ручной работы

Скачайте Pen для своей ОС с [официальной страницы](https://www.pen.dev/downloads). Windows: запустите установщик. macOS: перенесите приложение из DMG в Applications. Linux: выберите AppImage или tarball своей архитектуры. Запустите приложение и войдите в свой аккаунт при запросе. Подробности — [официальная инструкция установки](https://docs.pen.dev/getting-started/installation).

Откройте `.pen` через Open File на стартовом экране или перетащите файл на dashboard. Для полной рабочей области выберите `pen/dts-workbench.pen`; для первого знакомства — `pen/screens/09-history.pen`.

Альтернатива: установите расширение **pen.dev** в VS Code или Cursor и откройте `.pen` там. Если вместо холста виден текст, проверьте расширение и выполните `pen.dev: Toggle Design Mode` через Command Palette. Не редактируйте содержимое файла как JSON.

Шрифты макетов — **IBM Plex Sans** и **IBM Plex Mono**, включая кириллицу. Если после открытия шрифты подменились и подписи сместились, проверьте доступность этих семейств; при необходимости установите их из [официального IBM Plex](https://github.com/IBM/plex), затем переоткройте Pen. Шрифты в этот репозиторий не включены.

## 3. Как участнику поправить экран без агента

1. Создайте свою Git-ветку, например `design/your-name-history`, и откройте основной `.pen`. Либо начните с отдельного экрана, чтобы не работать на большом холсте.
2. Найдите экран в Layers. Актуальные дополнительные корни называются `Carbon · …`; корень истории — `bvyQ9`, исследования — `qUCbQ`. Полный индекс — [manifest.json](manifest.json).
3. Выделите нужный текст или элемент в Layers. Меняйте текст, положение, размер и оформление через редактор и панель свойств. Для перемещения используется `V`, для текста — `T`, для перемещения по холсту — `H`.
4. Используйте цвета переменных `dts.*`. Смена общего токена влияет на несколько экранов; локальная правка текста не требует менять палитру. Не перекрашивайте температурную шкалу как обычный UI-акцент.
5. Проверьте экран целиком: подписи осей и единицы, отсутствие перекрытий, читаемость, состояния кнопок. Посмотрите PNG до правки как ориентир. Не меняйте научные значения ради композиции.
6. Сохраните `Ctrl+S` / `Cmd+S`. Для отдельного варианта используйте Save As. В общем проекте исходные корни Захара `wEubH`, `EyEym`, `p0SpzX`, `hw2nd` сохраняйте без изменений, если задача прямо не относится к ним.
7. Экспортируйте исправленный экран и приложите `.pen` + PNG к своей ветке или PR.

На Windows/Linux в сочетаниях используется Ctrl, на macOS — Cmd. Полный список — [клавиатурные команды Pen](https://docs.pen.dev/core-concepts/keyboard-shortcuts). Для навигации и свойств ориентируйтесь на свою версию приложения.

## 4. Подключение агента через MCP

Откройте нужный `.pen` в запущенном Pen. В Settings → MCP включите интеграцию своего клиента, затем перезапустите клиент и проверьте наличие сервера **pencil**. Для Codex/ChatGPT интеграция в Pen называется **Codex CLI**; для Claude Code — **Claude Code CLI**. Поддерживаемые клиенты зависят от установленной версии. Источники: [AI Integration](https://docs.pen.dev/getting-started/ai-integration), [Installation](https://docs.pen.dev/getting-started/installation).

MCP — канал, через который внешний агент читает и меняет холст. Наличие PNG в контексте агента само по себе не даёт ему возможности изменить слои `.pen`.

Дайте агенту абсолютный путь к файлу на **вашей** машине. Пути `C:/dev/mgts/...` из сессии автора не переносимы на другой компьютер. Если сервер не виден: проверьте, что Pen запущен, документ открыт, интеграция включена, клиент перезапущен. Не подставляйте путь к MCP-бинарнику с чужого компьютера.

### Готовый стартовый промпт

Подставьте свой путь и конкретную задачу:

```text
Работаем над DTS Workbench в ветке фронтенда.
Прочитай design/carbon-r2/AGENTS.md, PEN_GUIDE.md, STYLE.md и manifest.json.
Файл Pen: <абсолютный путь к design/carbon-r2/pen/dts-workbench.pen>.
Задача: <конкретная правка и экран>.

Сначала через pencil прочитай read_skill(), затем pen-schema.md и execute.md.
Вызови get_app_state() и проверь, что открыт нужный документ.
Через execute/Get найди нужный корень; не читай .pen файловыми инструментами
и не изменяй его как JSON. Перед правкой изучи слои и переменные.

Сохраняй Carbon, белую рабочую поверхность, IBM Plex и семантику графиков.
Исходные экраны Захара и другие экраны без необходимости не меняй.
Не придумывай экспертные ответы, предсказания, метрики ML и измерения.
После правки проверь геометрию через Get с visitor, посмотри TakeScreenshot,
сохрани документ на диск и экспортируй изменённый экран в PNG 2x.
Сообщи, какой .pen сохранён, какие PNG обновлены и что ещё не реализовано.
```

Агенту для обычных текстовых и композиционных правок не нужны CSV или установка ML-зависимостей. Графики здесь векторные, но не являются интерактивным вычислительным движком: пересчёт сигнала требует отдельной работы с данными.

## 5. CLI — дополнительный способ для агентов и экспорта

Для ручной правки достаточно приложения. Для терминального режима установите **Node.js 22.19 или новее**, затем CLI. Версия Node проверяется `node --version`.

```sh
npm install -g @pen.dev/cli
pen version
pen login
```

CLI имеет отдельную авторизацию Pen. Если запускаете модель через `--agent codex`, для авторизации этого провайдера в установленной у автора версии предусмотрен `pen codex-login`; сверяйте доступные команды через `pen --help`. Другие провайдеры настраиваются отдельно. Источник: [официальный CLI reference](https://docs.pen.dev/for-developers/pen-cli).

### Точная работа с открытым desktop-документом

Из корня репозитория:

```sh
pen interactive -a desktop -i design/carbon-r2/pen/dts-workbench.pen
```

Далее это команды **внутри Pen shell**, а не команды PowerShell/bash:

```javascript
read_skill()
read_skill({path:"pen-schema.md"})
read_skill({path:"execute.md"})
get_app_state()
execute({input:'Print(Get("bvyQ9", {depth:1}));'})
execute({input:'TakeScreenshot(["bvyQ9"]);'})
execute({input:'Export(["bvyQ9"], "png", "design/carbon-r2/export-local", {scale:2});'})
save()
exit()
```

`Export` создаёт файл с ID корня, например `bvyQ9.png`. Для публикации используйте понятное имя `09-history.png` и обновите индекс. При диагностике `Get` с visitor позволяет читать только необходимые данные и находить clipping. Если `execute` завершился ошибкой с `editId`, исправляйте его через `edits`, а не повторяйте тот же ошибочный блок.

### Отдельная копия без GUI

```sh
pen interactive -i design/carbon-r2/pen/screens/09-history.pen -o history-my-edit.pen
```

Прочитайте инструкции, выполните правку через `execute`, затем `save()` и `exit()`. Исходный файл остаётся отдельным от выбранного вывода. Отдельный экран сохраняет ID корня, поэтому для истории используется тот же `bvyQ9`.

Desktop и headless CLI могут давать немного разные пиксели при растеризации: при проверке R2 идентичность файлов PNG не получена. Эталонные картинки в `png/` экспортированы из desktop. Сравнивайте прежде всего слои, подписи, данные и геометрию, а итоговый вид проверяйте визуально; при заметной подмене шрифта проверьте IBM Plex.

Не полагайтесь только на exit code: после сохранения проверьте существование `.pen`, после экспорта — PNG, затем откройте результат в Pen. В этом пакете общий файл и отдельные экраны сохранены через редактор/CLI, а не созданы вручную из текстового описания.

## 6. Сохранение, Git и согласование

Сохраните и закройте документ перед переключением ветки или pull. Для параллельных правок используйте отдельные ветки и копии. Конфликт `.pen` не разрешайте вручную как текст: сохраните обе версии, выберите основу и перенесите другую правку средствами Pen. Подход соответствует [рекомендациям по .pen и Git](https://docs.pen.dev/core-concepts/pen-files).

Отдельные `.pen` нужны для самостоятельной правки одного экрана, но итоговую согласованную версию внесите в `pen/dts-workbench.pen`. После переноса проверьте экран в общем документе и переэкспортируйте его. Если при копировании изменились ID, обновите `manifest.json` и `pen/screens.json`; не полагайтесь на прежние ID.

Перед коммитом: `.pen` сохранён; PNG соответствует ему; в README есть актуальная ссылка; видео отсутствует. В ветке `web` push запускает staging workflow, поэтому для публикации только макетов в этой поставке использовано `[skip ci]`. Изменение приложения и его проверок — отдельная задача.

## 7. Быстрый экспорт PNG вручную

Выделите корень экрана, внизу панели свойств выберите PNG и масштаб 2x, нажмите Export layer. При выборе нескольких экранов Pen может сформировать ZIP. Выбирайте frame целиком, а не только график внутри него. Официальная инструкция: [Import & Export](https://docs.pen.dev/core-concepts/import-and-export).

Проверьте итоговый PNG открытием файла: история должна быть светлой, разбор события содержать два нижних графика, а сохранение ответа до выбора быть недоступным. Это быстрые признаки актуальной R2, позволяющие заметить случайный экспорт старого файла.
