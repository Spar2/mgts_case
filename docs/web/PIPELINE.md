## Согласованные поля

Отправка `POST /api/v2/analysis-jobs` с заголовком `Idempotency-Key`:

```json
{
  "region": {
    "record_id": "5",
    "row_start": 0,
    "row_end": 32,
    "column_start": 0,
    "column_end": 64
  },
  "source_sha256": "64 hex"
}
```

Индексы полуоткрытые. Метод и версию назначает сервер. Повтор того же ключа и того же тела возвращает ту же задачу. Другое тело с тем же ключом — отказ 409.

Просмотр: `GET /api/v2/analysis-jobs/{id}` отдаёт `status`, `stage`, `region`, `source_sha256`, `method`, `method_version`, `cancel_requested`, `run_id`, `error`. Стадия берётся только из этого ответа. Проценты клиент не вычисляет.

Отмена: `POST /api/v2/jobs/{id}/cancel`. На экране после запроса показывается повторно прочитанный статус, а не локально выдуманное «завершено». Обрыв HTTP-запроса отмену не вызывает.

Результат: `GET /api/v2/result-runs/{id}`, срезы `.../slices`, поле `.../tiles?layer=`, зоны `.../zones`. Разность — слой `difference`, это обработка − исходник. Score показывается с именем, единицей, смыслом, порогом и правилом сравнения и не называется вероятностью.

Ссылка задачи — внутренний путь `/pipeline?job_id=...`. После обновления страницы `job_id` читается из адреса. Внешний URL в ссылку задачи не принимается.

Черновик окна, отправленное тело, `job_id` и показанный `run_id` хранятся раздельно. Смена черновика не переписывает отправленное тело. Поздний ответ сохраняет принятую задачу, но не меняет актуально выбранные источник и окно. Неприменённые границы применяются кнопкой «Применить окно» либо Enter; «Рассчитать» использует введённые границы.

Последующий аудит и актуальные проверки: [PIPELINE-REVIEW-2026-10-15](PIPELINE-REVIEW-2026-10-15.md). Описание первого прогона ниже сохранено как история; прежнее удержание максимальной высоты заменено ограниченной областью с внутренней прокруткой, без глобального scrollTo.

## Журнал

Ответственные за этот этап: маршрут и пункт меню — `main.tsx` и `auth-navigation.ts`; окно, ключ и ссылка — `pipeline-state.ts`; экран — `pipeline.tsx` и `pipeline.scss`. Серверные маршруты расчёта не менялись. Кнопка «Проверить» не добавлялась: отдельного preflight без создания задачи и без резервирования в API нет.

Согласованное тело запроса — объект `region` плюс `source_sha256`, как в примере выше. Индексы полуоткрытые. Метод назначает сервер.

Найденные дефекты и исправления:

- Срез сохранённого run уходил методом POST и получал 405. Сигнал отмены передавался вторым аргументом и становился телом. Вызов переведён на GET. После этого блок «Очистка» показал разность «обработка − исходник».
- Переключение на «Очистка» сдвигало страницу: панель становилась короче после загрузки графика, и браузер поджимал прокрутку. Высота панели удерживается по уже показанному максимуму, позиция прокрутки возвращается. Выбор точки и обновление статуса задачи страницу не двигают.
- На ширине 320, 390 и 430 длинные SHA и `run_id` раздвигали страницу по горизонтали. Перенос длинных строк включён только в стилях этого экрана. Повторный замер дал нулевой горизонтальный выступ.

Проверки, все с кодом 0:

- Два прогона pytest: viewer получает 403, чужой SHA — 409, окно вне записи — 422, чужой проект отвергнут, тот же ключ и то же тело дают один `job_id`, `POST /api/v2/jobs/{id}/cancel` возвращает подтверждённый сервером статус `cancelled`.
- Отдельный прогон среза: `run_id` и SHA совпадают с сохранённым run, разность равна обработке минус исходник, пустая ячейка остаётся пустой.
- Два прогона Vitest, 7 тестов: полуоткрытое окно, внутренняя ссылка `job_id`, черновик не меняет отправленное тело, ключ идемпотентности меняется только вместе с телом, помощник сам второй POST не отправляет.
- Живой ограниченный расчёт записи `6`: job `501ba92b7bc74cc4aba3df196df2a314`, статус `complete`, run `266d0e2bd36ffbb42acc59d5c51eeb2de2f165b966882712527f2117f2be1bbd`. Повтор того же тела не создал вторую задачу.
- `npm run build` и проверка OpenAPI без расхождения. Заморозка UI после обновления только разрешённых сумм: 73 файла, расхождений нет.
- Chromium прошёл выбор записи, смену окна, точку, четыре блока, повторную загрузку с тем же `job_id` и переход в `/analysis`. Tab доходит до «Рассчитать». Firefox установлен, но эта сборка Playwright его не запустила. Движка WebKit в среде нет. Оба отмечены как непроверенные.

Команды этого этапа, без паролей и cookie: `pytest` двух новых случаев, `vitest` файлов `pipeline-state.test.ts` и `auth-navigation.test.ts`, `npm run build`, `python scripts/export-openapi.py --check`, `python scripts/check-web-ui-freeze.py`. Коммит, push, merge и выкладка не выполнялись.

## Контракты следующего этапа

Ниже только будущие контракты. Этих возможностей на экране нет, заглушек и кнопок для них нет.

1. Обучение. Нужен отдельный вид задачи, свой набор данных и запрет записывать экспертский журнал как обучающие метки. Текущая кнопка «Рассчитать» обучение не запускает.
2. Произвольный Python. Нужно изолированное исполнение и явный запрет на текущем worker. Сейчас исполнимого кода со страницы загрузить нельзя.
3. Перестановка операций. Нужен граф операций, который исполняет сервер. Сейчас worker выполняет один закреплённый метод целиком, без конструктора порядка.
4. Новые фильтры и детекторы. Нужен новый закреплённый метод и его SHA. Переключатель в интерфейсе метод не создаёт и текущий SHA не меняет.
5. Большой HTTP-импорт. Нужны лимит тела, проект и автор. Текущий импорт читает подготовленный каталог, не произвольную загрузку со страницы.
6. Редактор меток. Нужно отдельное хранилище обучающих меток. Экспертный журнал и ответы кейса этим хранилищем не являются.
7. Cross-validation. Нужен определённый протокол и конкретная обучаемая задача. Для очистки возможна проверка восстановления с разделением по времени; для независимой оценки обнаружения аварий нужен соответствующий эталон событий. Такие метрики экран сейчас не вычисляет.
