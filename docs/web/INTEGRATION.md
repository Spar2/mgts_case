## Научный контракт

- General: `0=valid`, `1=sentinel (-300)`, `2=nonfinite`, `4=absent_tail`. Обзор добавляет `8=no observations/gap` как состояние отображения, не меняя raw-маску.
- ML: исключает все `T <= -200`; его коды причин отличаются. Они не подменяют исходные коды. Gateway отклоняет обработку, если это правило отбросило бы валидное нативное измерение.
- В поле температура передаётся float32 ради памяти/трафика; исходные float64 остаются read-only. Числовые API-срезы сохраняют исходную точность. При проверке чисел используется срез, а не цвет или округлённая GPU-копия.
- Часовой пояс неизвестен у `local_unzoned`. UTC не угадывается. Время на осях — исходный elapsed seconds; timestamp инспектора сохраняет исходный текст/смещение.
- Обзор считает медиану валидных исходных наблюдений **непосредственно внутри физического бина**. Медианы меньших бинов не усредняются в новые уровни. Пустые бины остаются пустыми. Бин, пересекающий разрыв >300 секунд, подавляется целиком — это консервативная потеря обзорной детализации; точное окно показывает оба сегмента с разрывом.
- Нативные ячейки размещаются по настоящим координатам; границы ячеек вычислены через соседние центры. У временного разрыва границы ограничены обычным шагом, промежуток остаётся пустым.
- При приближении, когда число исходных строк/координат не превышает запрошенный размер блока, `/tiles` переключается на `native_observations`. Мелкие обзорные бины не изображают ложные пропуски между обычными соседними измерениями. Шкала источника сохраняется.
- Прореживание линий сохраняет экстремумы, исходные x и null-маркеры разрывов. Исходные срезы не прорежены и доступны численно.

## Границы первого этапа (историческое описание)

Текущее выполнение командных задач использует PostgreSQL, persistent blobs, lease и ограничения очереди; подключён потоковый эпизод Redis/ClickHouse. Следующие абзацы описывают ранний локальный этап, а не текущую готовность командного доступа.

Сервис анализа ограничивает вход миллионом ячеек. Веб предлагает малое окно вокруг выбранной точки, выполняет один job одновременно и хранит максимум 16 результатов. Процент не выдумывается: `running` имеет неопределённый прогресс, `complete` — подтверждённый результат. Replay-сессии находятся в памяти. Задачи сохраняются в workspace.sqlite3; незавершённые после перезапуска получают interrupted. Экспертные ответы остаются в отдельных SQLite-журналах.

Поток ответа ML ограничен 8 MiB на задачу. Сумма сохранённых сериализованных результатов — до 16 MiB; старые завершённые задачи вытесняются. Это лимит JSON-полезной нагрузки, а не точное измерение памяти Python. Слишком большой ответ завершает задачу явной ошибкой, не усечённым результатом.

Детектор выдаёт пространственные/формовые гипотезы. Поля `expert_confirmed=false` и `trained_classifier_operational=false` остаются в результате. Веб-интерфейс не заявляет измеренное качество обнаружения и не делает оперативной тревоги.

Существующий LAN контракт пока не предоставляет полноценного каталога записей. В `profiles_raw` нет необходимой привязки к source SHA/проекту; `queued=true` означает приём в Redis, а не подтверждённую запись ClickHouse. Перед live-интеграцией требуются идентичность источника, дедупликация, watermark сохранённых профилей и согласованный адаптер. Потребитель веба не должен перехватывать сообщения группы ingester.

Будущий adapter отдаёт те же метаданные, физические блоки и точные срезы. Redis/ClickHouse и producer-токены недоступны браузеру. Replay использует собственные ограниченные сессии, REST-команды и SSE-курсор; температурные массивы через SSE не передаются.

## Права и эксплуатация первого этапа (историческое описание)

Сейчас идентичность рабочего контура берётся из серверной cookie-сессии; приглашения, роли проекта, ревизии, CSRF, Redis-ограничения и backup/restore реализованы. Инструкции: [TEAM-ACCESS](TEAM-ACCESS.md), [PRODUCTION-OPERATOR](PRODUCTION-OPERATOR.md). Следующие абзацы сохранены как описание старого локального режима; они не являются рекомендацией открыть его в интернет.

Локальное имя эксперта — self-declared identity. Это не корпоративная аутентификация и не проверка квалификации. Аутентифицированный командный этап должен заменить identity на серверную сессию, проверять project membership/назначение/revision на каждой операции, ввести TLS и решить миграцию общего журнала. До этого bind/Compose остаются loopback.

Новый UI передаёт independent=true, пакет очереди и заявленное имя эксперта. Для каждого имени и SHA очереди отдельный журнал; методы раскрываются после ответа именно этого имени. Старый общий журнал доступен через прежние API для совместимости. Это разделение локальной работы, а не защита публичного сервера: имя можно заявить другое. Командный этап должен связать журналы с подтверждённой серверной сессией.

SQLite WAL/FULL и журнал ревизий подходят локальному пилоту. Для общего сервера отдельным этапом нужны резервное копирование и проверка восстановления, наблюдение за задачами, лимиты запросов по пользователю и решение по общей БД. Наличие Dockerfile не означает выполнение этих работ.

## Подключённое расширение real-data-v2

Исследован checkout `sol-ml-hardening` на `707768872fc386f03967c5630d30be40a6f29b26`; адаптер использует опубликованный пакет с manifest.schema=`real_data_pack_v1`. Его собственные source/patch SHA остаются доказательством конкретных данных, коммит checkout их не заменяет. Weak labels используются только для восстановления предложений, не как человеческие ответы.

`workspace.adapt_real_pack` сверяет каждую ячейку с native general-источником в точности исходного Float32 пакета, затем сохраняет native-значения без понижения точности. Причины качества явно переводятся: Sol 1=nonfinite, 2=sentinel; general 1=sentinel, 2=nonfinite. Невалидность и координаты проверяются до публикации очереди; ошибка останавливает запуск. Исходный пакет монтируется read-only; производные NPZ и независимые журналы находятся в постоянном runtime-томе.

История метаданных постоянная; UI показывает последние 500 запусков. Бюджет сохранённых payload workspace — 32 MiB, старые результаты вытесняются с явной отметкой. Старый лимит 16 MiB относится к быстрому in-memory кэшу ML-задач. Отмена ожидает окончания внешнего HTTP-вызова и отбрасывает его ответ; процесс ML не прерывается.
