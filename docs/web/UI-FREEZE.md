# Зафиксированный интерфейс веб-платформы

**Основание:** прямое поручение пользователя от 15 октября 2026:
«зафиксируй веб дизайн в текущем состоянии» и запрети изменения лендинга,
разделов и переключений без явного разрешения.

**Эталон:** `web-ui-2026-10-15`, Git tag `web-ui-freeze-2026-10-15`.
Точный коммит: `git rev-parse web-ui-freeze-2026-10-15^{commit}`.
Список файлов и контрольные суммы: [frozen-ui.json](design-system/frozen-ui.json).
Это локально зафиксированная версия; публикация и deployment требуют отдельного
поручения. Архивные Pen/PNG не являются альтернативой эталону.

## Правило разрешений

По умолчанию текущий интерфейс **не изменяется**. Нельзя переименовать,
переставить, удалить или добавить раздел; переписать лендинг; менять маршруты,
входную страницу, навигацию, взаимодействия или стили по собственной инициативе.
Обновление зависимости или серверного HTML, меняющее UI косвенно, также является
изменением защищённого интерфейса.

Разрешение должно исходить от пользователя и называть конкретное изменение,
экран или поведение. Уже данное явное разрешение в рамках той же задачи не нужно
спрашивать повторно. Но оно не распространяется на соседние разделы.

| Поручение | Граница допустимого |
| --- | --- |
| «Исправь скачок при выборе шага демонстрации» | Устранить этот скачок, сохранить состав/порядок шагов, тексты и остальную навигацию |
| «Сделай заголовок лендинга крупнее» | Изменить указанный размер; не перестраивать лендинг и остальные страницы |
| «Подключи расчёт ML», «проверь БД», «исправь сервер» | Работать с данными/сервером, сохранив текущий внешний контракт; новый UI сначала согласовать |
| «Улучши сайт», «сделай красиво», «отрефактори» | Проанализировать и предложить конкретную правку; это не разрешение менять защищённый UI |

До редактирования агент кратко фиксирует область задачи и нужные файлы. Делать
разрешённую работу следует без лишних подтверждений. Когда требуемое изменение
не разрешено, нельзя сначала применить его, а затем спрашивать одобрение.
Нужно продолжить независимую разрешённую часть и пояснить, какое изменение UI
нуждается в согласовании и почему.

## Неприкосновенный лендинг

Защищена **вся страница `/`**, а не только перечисленные детали:

- Название «Единая аналитическая платформа сенсорных данных», структура первого
  экрана, тексты, якоря и действия входа.
- Реальный ограниченный пример `5.csv / review-00018`: исходные значения,
  координаты, время, маски и происхождение. Не заменять декоративным графиком,
  синтетическими метриками или выдуманным результатом модели.
- Вкладки «Предобработка», «Очистка от шумов», «Аномалии», «Компьютерное зрение»,
  «Трансформеры», их текущий порядок и различающиеся визуализации. Начальная
  вкладка — **«Предобработка»**. Исследовательские схемы не объявлять результатами
  работающей модели.
- Текущие блоки возможностей, передачи кейса и доступа. Не добавлять командные
  биографии, цифры достижений, слоганы или новые секции без согласования.
- Логотипы МГТС и LARP CORP: оригинальные изображения, одинаковые квадратные
  размеры, **без обрезки**, между ними `×`. Сохранить текущую компактную группу
  слева и текст справа. Не возвращать подпись под логотипы и не перемещать группу.
- Файлы `landing.tsx`, `landing.scss`, `public/landing/` и связанные общие стили.

## Неприкосновенная навигация и вход

Рабочее меню — **одна прямая полоса**, строго в этом порядке:

| Текст | Маршрут |
| --- | --- |
| Исследование | `/research` |
| Экспертная проверка | `/review` |
| Кандидаты | `/candidates` |
| Запуски | `/runs` |
| ML-графики | `/analysis` |
| Кейсы | `/cases` |
| Демонстрация | `/demo` |
| Система | `/system` |
| Аккаунт | `/account` |

- Не возвращать группировку «Работы / Архив / Мониторинг / Лаборатория / Кейсы /
  Другое», не переименовывать «Исследование» в «Архив», не создавать вторую
  полосу навигации и не прятать привычные разделы в новый dropdown.
- Существующие прямые маршруты `/works`, `/monitoring`, `/laboratory`,
  `/experiments` и ссылки из рабочего контекста сохраняются. Их не удалять и
  не продвигать в главное меню без разрешения.
- `/` всегда открывает лендинг, в том числе для вошедшего участника. Название
  платформы в рабочей шапке ведёт на `/`.
- Безопасный вход без `next` ведёт в `/research`. При входе по разрешённой
  внутренней ссылке возвращается её контекст. Выход ведёт на `/` и сохраняет
  действующую очистку пользовательских кэшей.
- Закрытые разделы требуют сессию. Не убирать AccessGate, проверки роли/проекта,
  CSRF, очистку кэша, серверные ограничения или защиту журнала ради удобства UI.
  Существующий локальный вход относится к dev-серверу и не является разрешением
  добавлять обход входа на командном стенде.

## Неприкосновенные разделы

Это правило распространяется **на каждый существующий экран**, включая формы
входа/приглашений/восстановления, исследование, проверку, кандидатов, запуски,
ML-графики, кейсы и их показ, систему, аккаунт и прямые рабочие маршруты.

Защищены состав блоков, их порядок, подписи, поля и кнопки, логика действий,
подключённые реальные данные, состояния ошибок/загрузки, мобильная компоновка,
клавиатура и навигационные связи. Нельзя автоматически применить новый шаблон
ко всем страницам или «исправить заодно» общий стиль.

Carbon, IBM Plex Sans/Mono, обе темы White/Gray 100 и действующие рабочие
поверхности и синий акцент сохраняются. Не заменять UI-библиотеку, тему, шрифты,
типографику, сетку или зависимости ради нового визуального направления.
Точные значения берутся из кода и [Design Guide](STYLE-AND-IDENTITY.md).

## Неприкосновенная демонстрация

Пять шагов и их порядок: **01 Измерение → 02 Наблюдение → 03 Сравнение →
04 Проверка → 05 Отчёт**. У каждого остаётся своя задача, описанная в
[DEMONSTRATION-GUIDE](DEMONSTRATION-GUIDE.md).

Особенно защищены:

1. Общая геометрия всех шагов: одинаковая высота внешней рабочей области,
   неподвижные полоса шагов и нижняя навигация. Высота сейчас ограничена
   `clamp(560px, calc(100dvh - 240px), 900px)`.
2. Прокрутка длинных материалов **внутри** рабочей области. Новый шаг открывает
   её начало; `window.scrollY` не сбрасывается. Не добавлять `window.scrollTo`,
   `scrollIntoView` для заголовка, глобальные циклы удержания прокрутки или
   анимированную смену высоты.
3. Заголовок шага не получает принудительный фокус и синюю рамку. Клавиатурный
   focus-visible кнопок остаётся доступен. Обычные стрелки/Home/End работают
   в полосе шагов; Ctrl/Meta/Alt не перехватываются. Ввод текста не меняет шаг.
4. Предварительно зарезервированные размеры графиков, стабильные подписи и
   отсутствие серого прямоугольника под короткой боковой панелью.
5. Выбор точки и ввод индекса: применяется по Enter/завершении ввода или явным
   кнопкам; переход шага не запускает обработку. Смена точки не двигает страницу.
6. Последний успешный срез остаётся при загрузке/обрыве связи с явным статусом.
   Устаревшая выборка не используется для расчёта, сохранения или экспорта.
   Кэш и черновик не переносятся в другую репетицию.
7. Совместимость source SHA, строки, окна и результата. Общие оси исходника и
   обработки; разность **обработка − исходник** с симметричной шкалой. Маски,
   реальные координаты, разрывы времени и неизвестный часовой пояс сохраняются.
8. Референсный фильтр не становится финальной ML-моделью. Изменение сигнала не
   называется доказанным шумом или качеством детекции аварий.
9. Репетиционный ответ сохраняется отдельно от рабочего журнала. Отчёт содержит
   сохранённый ответ; несохранённый черновик явно отмечается. Выход из репетиции
   отключает запись до явного возобновления. Обработка и технический replay
   запускаются только пользователем.

## Проверка и разрешённое обновление

```powershell
python scripts/check-web-ui-freeze.py
```

Проверка сравнивает список и SHA-256 файлов с эталоном. Текст нормализуется
только по CRLF → LF, чтобы Windows/Linux не создавали ложное расхождение.
Появление, удаление и изменение защищённого файла приводят к ненулевому коду
возврата. Проверка включена в GitHub workflow; этот коммит её только
подготавливает, не является подтверждением уже пройденного запуска GitHub.

Это защита от случайных правок и правило работы моделей, **не ACL и не гарантия
против намеренного обхода**: редактор с правом записи способен изменить и
manifest. Поэтому запрещено самовольно переписывать manifest, этот документ,
AGENTS или ослаблять тесты для обхода проверки.

Когда пользователь явно разрешил конкретную правку:

1. Зафиксировать её границы; сохранить изменения других участников.
2. Внести только разрешённое изменение. Не откатывать весь frontend на старый
   коммит и не брать шаблоны из `design/archive/`.
3. Проверить нужный экран и неизменность остальных защищённых областей;
   выполнить подходящие тесты, TypeScript/build/lint. При работе с переходами
   сверить геометрию и прокрутку, а не только скриншот первого кадра.
4. Записать основание и проверку в журнал ниже. Только затем осознанно обновить
   контрольные суммы действительно разрешённых файлов. У проверки нет `--update`.
5. Показать diff и результат. Commit/push/merge/deployment требуют своего
   пользовательского поручения; разрешение изменить UI их не подразумевает.
