# Проверка и исправление вкладки «Пайплайн»

15 октября 2026. Проверен локальный checkout `C:\dev\mgts\web-design`, HEAD `6ceca9a3031842a4dcd2814b9e08c2c408385f6e` с незакоммиченными изменениями вкладки. Проверяющий агент не выполнял commit, push, merge или deployment.

## Вывод

Основа соответствует первому этапу: авторизованный экран использует существующий закреплённый worker, реальные записи, очередь и бинарные сохранённые результаты. Новый вычислительный движок, обучение и подмена отсутствующих слоёв не добавлены. В главном меню добавлен ровно один пункт после «ML-графики». Остальные страницы и их стили не перестраивались.

Первоначальная реализация содержала ошибки состояния, ввода и восстановления. Они исправлены и воспроизведены в браузере на реальных ответах API. Это готовность проверенного первого локального этапа; полноценный редактируемый конструктор и production-публикация этим не подтверждаются.

## Найдено и исправлено

| Проблема | Исправление и подтверждение |

| Поздний POST возвращал прежнюю запись, хотя пользователь уже выбрал другую | Удалено принудительное назначение источника из ответа. Реальный ответ 202 удержан через CDP, запись изменена, ответ отпущен; выбор новой записи сохранён, принятая задача подписана собственным окном. |

| Неизвестная запись и неверные границы молча заменялись начальными | Явно заданные неверные параметры остаются ошибкой. Автоматический небольшой участок выбирается только при отсутствии границ. |

Проверено применение [774,822) × [2031,2504) без потери любого из четырёх значений. «Рассчитать» использует введённые границы. |

| Паспорт сохранённого результата не раскрывал происхождение | Добавлены метод, версия, источник/SHA, происхождение обучения, исследовательский статус, ограничения и параметры именно выбранного run. |

## Проверки

- Клиент: **46 тестов**, ESLint, TypeScript и production build прошли.
- Сервер: **134 теста прошли**, три проверки реальных данных были пропущены в изолированном прогоне фикстур. Затем эти **три проверки отдельно прошли** на смонтированных read-only настоящих записях и очереди. Итого подтверждены все 137 случаев двумя соответствующими окружениями.
- Использован отдельный временный контейнер из образа worker с научными зависимостями, временные PostgreSQL-схемы с teardown. В тестовом контейнере отключён встроенный публичный демопакет образа, чтобы не менять смысл legacy-фикстур. Рабочие сервисы и конфигурация доступа не менялись.
- OpenAPI: `scripts/export-openapi.py --check` прошёл, новых серверных маршрутов этот аудит не добавлял.
- Настоящие расчёты из интерфейса: все шесть записей, ограниченные окна [0,32) × [0,64), статусы `complete`, у каждой свой сохранённый run.
- Дополнительно рассчитано реальное окно записи 6: строки [774,822), столбцы [2031,2504). Получена одна гипотеза зоны Local_Heating. Это не подтверждение причины или качества обнаружения.
- Независимая числовая сверка ответа реального среза: 473 сопоставимые пары, строка 775, столбец 2031. Максимальная ошибка равенства `difference = processed − raw` равна **0**; среднее абсолютное изменение **0.35151786481603253 °C**. Это изменение сигнала, не качество очистки.
- Потеря POST-ответа **после принятия задачи сервером**: ручной повтор сохранил тело, Idempotency-Key и первоначальный `job_id`. Дубликат не создан.
- Проверены восстановление задачи по ссылке, переход в `/analysis` с теми же run/SHA/окном/точкой/зоной, сетевой отказ среза и явное восстановление, клавиатура и reduced motion.
- Chromium: размеры 320/390/430/1440 px, по четыре блока на каждом размере. Горизонтальный выступ 0; высота рабочей области 660 px при viewport height 900; высота документа одинакова между блоками каждого размера.
- Viewport, перехват Fetch и эмуляция reduced motion после проверки сброшены.

Начальный запуск вычислительных тестов в образе API не имел научных зависимостей и не использовался как успешное подтверждение. Полный успешный прогон выполнен в образе worker. Сначала полный набор также запускался с наследуемым встроенным демопакетом образа; это давало ожидаемые отказы анонимных legacy-фикстур. Конфигурация изолированного прогона исправлена, проверки доступа не ослаблялись.

## Что ещё не подтверждено и что делать дальше

- Firefox и WebKit этим аудитом не запускались. Локальная Chromium-проверка не заменяет их.
- Новый общий CI и удалённый стенд не проверены: публикации не было, текущие изменения не закоммичены.
- Вкладка исполняет один фиксированный метод. Настройки пока не сохраняются отдельной версионированной сущностью; нет истории работ и сравнения двух результатов внутри этого экрана.
- Для отдельной кнопки проверки нужен серверный preflight с общей валидацией submit. Сейчас бюджет окончательно проверяет существующий submit, фиктивной проверки нет.
- Новые регрессии состояния покрыты unit-тестами и фактической браузерной проверкой. Отдельного автоматически исполняемого CI-сценария `/pipeline` пока нет; это обязательная часть следующего этапа.
- Для обучения нужен конкретный тренер, ресурсы, набор данных и протокол оценки. Для кросс-валидации очистки возможен протокол восстановления с разделением по времени; независимая оценка обнаружения аварий требует соответствующего эталона. Отсутствие меток аварий не запрещает вообще любую проверку обучаемой очистки.
