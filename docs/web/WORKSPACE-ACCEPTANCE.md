## Нагрузка

[Измерения](measurements/product-20261014/load.json): цикл завершился после **не менее 1800 секунд**. Десять разных авторизованных аккаунтов, восемь analyst и два expert. 1690 чтений прогретых блоков/срезов/работ/потока, 456 успешных сохранений работ, p95 **126.45 мс**, ошибок чтения 0. Последние записи всех восьми analyst-работ перечитаны и совпали.

Среда: Windows, loopback FastAPI, отдельная PostgreSQL-схема; выделенные Docker Redis/ClickHouse/ingester. Это не измерение удалённого сервера или физического телефона. Запросы выполнялись десятью потоками циклически примерно каждые 10 секунд; это не доказательство высокой пиковой пропускной способности.

Последний request sample записан на 1796.547 с, затем цикл выдержал остаток до 1800 с. Поле `duration_s` оригинального старого отчёта было последним sample, а не временем выхода. Публикуются отдельно гарантированная завершённая длительность и время последней пробы; код будущего прогона записывает фактическое время выхода.

Дополнительные 40 проб фактического Python API: RSS **307.28–313.68 MiB**. Исходные 30-минутные process samples оказались launcher и исключены из оценки API. Дополнительный период ограничен последней частью прогона; доказательство полного 30-минутного плато памяти этим не подменяется. Счётчики памяти Docker приведены с условиями в JSON.

[Перегрузка](measurements/product-20261014/queue-pressure.json) проведена во время этого прогона: 12 реальных одновременных POST расчёта, 10 accepted, два HTTP 429 + Retry-After. Вторая активная задача того же пользователя получает 429. Claim был кратко заблокирован транзакционной блокировкой QA-БД; принятые задания отменены явно, вымышленные расчёты не публиковались. Предел двух выполняемых задач дополнительно проверен конкурентным PostgreSQL-тестом `test_atomic_queue_capacity`.

## Исправления, найденные при приёмке

- FastAPI раньше не обслуживал прямые `/works/{id}`, `/laboratory`, `/monitoring`; добавлены маршруты shell и regression test без открытия API анонимам.
- Длинные версии в каталоге и SHA мониторинга переполняли 320 px. Добавлены переносы; сценарий проверяет также каталог с несколькими фактическими расчётами.
- На Windows читатель heartbeat иногда мешал атомарной замене и завершал worker. Ограниченный повтор только PermissionError/Windows сохраняет атомарность; постоянная ошибка продолжает явно падать, temporary очищается. Расчёты автоматически не повторяются. Три теста проверяют contention и постоянный отказ.
- Несовместимый второй результат в несохранённом контексте больше не отправляется на сравнение; показывается причина.
- Первый удалённый CI выявил Windows CRLF в manifest при LF в Git. Упаковщик теперь явно пишет LF; SHA закреплён по каноническим байтам Git, файлы receipt исключены из автоконверсии. Проверка целостности не ослаблена.
- При browser-offline открытый SSE не всегда немедленно даёт onerror. Явные offline/online listeners теперь сразу показывают разрыв и инициируют получение нового снимка при восстановлении. `qa-monitor-outage.js` проверяет сохранение профиля и восстановление без перезагрузки.
- Chromium, Firefox и WebKit прошли отключение/восстановление мониторинга. WebKit отдельно прошёл очередь 36 карточек: durable skip, клавиша 4 → unknown, Ctrl+Enter → сохранение и переход. Пропуск остался без экспертного ответа.
- Включён новый зелёный коммит команды `web:01cd4275ba2a45632c9fda29a8ee9eb22ab93fd1` (Nginx/import, APP_PORT, API errors). Его обработка HTML-ошибок прокси переиспользуется для `/api/v2`; два теста подтверждают сохранение HTTP-статуса и ключа PATCH без автоматических повторов.
