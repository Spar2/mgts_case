# Подготовка к защите: состояние 11 октября 2026

Рабочий путь: исходные измерения → выбранный расчёт → независимый ответ → автономный отчёт. Внешнюю публикацию пока откладываем по решению команды. Панель внешних моделей в этот этап не входит.

## Что изменено

В карточке участка можно подключить сохранённый профиль. Видны метод, версия, параметры, ограничения и **один ID для графика и отчёта**. «Запуски» открывают именно выбранный результат в исследовании. Ссылка паспорта и сам паспорт сохраняют его ID; сервер проверяет доступ, SHA, строку, покрытие и форму массива. Пропуски исходника и обработки остаются пропусками.

При смене профиля, области или метода обработка сбрасывается. Запоздавший ответ не возвращает старый выбор. Более новый расчёт другого участника не меняет выбранный результат. Без выбранного ID экспорт содержит исходные данные. Отчёт без экспертного ответа не требует выдуманного имени эксперта; при включении ответа прежняя проверка подтверждённой личности сохраняется.

## Данные и два контекста

Скрипт `scripts/defense-readiness.py` открывает шесть проверенных mmap-источников, сверяет точные срезы и маски, проверяет целостность очереди и два контекста ячейка-в-ячейку. Он не создаёт разметку и не выполняет обучение.

```text
python scripts/defense-readiness.py --records /path/to/records --queue /path/to/review-queue --output .runtime/defense-readiness.json
```

[Результат проверки реального архива](measurements/defense-readiness-20261011.json) содержит SHA, размеры, причины невалидности и переносимые маршруты. Основной контекст — `5.csv`, строки `[359,539)`, координаты `[192,204)`; резервный — `1.csv`, строки `[146,205)`, координаты `[591,710)`. Это проверенные исследовательские окна, физическая причина не установлена. Выбор финального метода и экспертного заключения для них ещё требуется.

## Передача расчёта Захара

Нужны фактический JSON результата и метаданные: SHA исходного CSV, исходная строка, полный профиль температур/`null`, координатная область, название и версия метода, параметры, время расчёта, происхождение обучения и ограничения. Не передавать anomaly score как температуру. Упаковка, ограничения размера и импорт описаны в [RESULT-HANDOFF](RESULT-HANDOFF.md). Веса нужны только для выполнения модели на сервере; для повторяемого показа достаточно проверенного результата.

## Стенд Гриши и выступление

Общий стенд пока не публикуется. Текущий workflow `Deploy web (staging)` на push выполняет проверки; deployment включается отдельным ручным флагом. Автоподъём на Xeon нельзя считать включённым. Перед его активацией нужно проверить изолированный каталог `/opt/haklolarp-web`, реальные read-only данные, PostgreSQL/runtime-тома, совместимость ClickHouse, HTTPS и конфигурацию приглашений. Затем привязать deployment к успешным checks, сохранить блокировку параллельных деплоев и проверять здоровье после обновления. Секреты остаются у оператора. Основной стек в `/opt/haklolarp-stack` не заменять веб-стеком.

Запуск участника — [README](README.md), эксплуатация — [PRODUCTION-OPERATOR](PRODUCTION-OPERATOR.md), сценарий выступления на 4–6 минут — [PRESENTATION-GUIDE](PRESENTATION-GUIDE.md). До готовности финального артефакта использовать честно обозначенный reference-фильтр. Перед защитой сохранить HTML/JSON, проверить их без сервера и провести репетицию с другим участником.

## Приёмка текущего изменения

- Клиентские тесты: 9 пройдено; lint, TypeScript и production-сборка.
- Браузерный сценарий `qa-selected-processing.js`: Chromium, Firefox, WebKit; скачанный JSON, сохранение ID при новом расчёте, маски, ссылка, сброс профиля/метода, поздний ответ; 320/390/430/1024/1440 px.
- Серверные проверки: 43 пройдено, 3 пропущено из-за условий окружения. Используются настоящий PostgreSQL/Redis в временных схемах; тестируются чужой проект, выбранный паспорт, неверный метод, SHA/строка/форма/покрытие и отсутствующий результат.
- Реальные массивы: шесть источников, 147 проверенных окон; числовые срезы sampled, оба контекста полностью сверены. Эта проверка не заявляет повторное сравнение всех CSV-ячеек.

Код изменения `f50f879f6de40045b7d52d419bf59e2e5c6a7b3b` прошёл [полный GitHub CI](https://github.com/werd0y45/haklolarp/actions/runs/38146700638): сборку, серверные контракты, OpenAPI, Compose, обычные и авторизованные браузерные сценарии. Deployment не запускался.

На свежем изолированном runtime с настоящим архивом импортирован сохранённый `median_x3` для строки 536. Скачанный отчёт выбранного окна точно совпал с этим результатом и исходной маской. Это reference-обработка, не финальная модель Захара. Локальные UI/API на 8081 обновлены; существующий CPU ML API на 8082 восстановлен.

[Свежие измерения](measurements/defense-performance-20261011.json): первое полезное поле 498 мс при 1440 px и 813 мс при 390 px; медиана прогретого переключения 43 мс в обоих случаях; разворачивание поля 59/31 мс. После выхода из исследования активных worker и WebGL-контекстов нет. Windows, headless Chromium 155, loopback, шесть настоящих записей; действия включают накладные расходы Playwright. Данные RAM и CPU сохранены в отчёте; точная модель CPU ОС не сообщена. Это 36 переключений, не физический телефон и не 30-минутная проверка replay.

Финальная готовность к защите ещё требует выбранного командой ML-результата, независимой репетиции запуска и позднее — проверки deployment на железе Гриши. Прошлые нагрузочные измерения не заменяют приёмку будущего внешнего стенда.

## Офлайн-передача кейса

В интерфейсе появились неизменяемые кейсы, предпросмотр импорта и скачивание полного ZIP: [CASES](CASES.md). Локальный основной и резервный кейсы подготовлены на реальных источниках; экспертных ответов к ним не добавлено. Новый браузерный сценарий включён в CI с проверкой фактического успешного результата.

`scripts/verify-evidence.py` позволяет другому участнику сверить скачанный JSON обычного исследования с подготовленным исходником и сохранённым JSON запуска без сервера. [Инструкция](RESULT-HANDOFF.md#независимо-сверить-скачанный-отчёт). На реальном `5.csv`, строке 536, окне `[359,539) × [192,204)` проверены raw-only и выбранный reference-расчёт: 12 точных профильных значений и 768 обзорных ячеек, координаты, маски, время, статистики и происхождение. Поле обзора остаётся подвыборкой, не полным окном.

11 автоматических проверок покрывают правильную передачу и подмену SHA, координат, пропусков, временной оси, профиля, происхождения и ID. Утилита не подтверждает точность модели, экспертный ответ или авторство; исходные файлы также должны поступить из доверенного архива. Никаких новых ML-результатов или обучающих меток эта доработка не создаёт.
