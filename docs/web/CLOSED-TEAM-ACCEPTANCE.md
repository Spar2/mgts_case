# Закрытый командный режим: локальная проверка

Дата: 15 октября 2026. Рабочая ветка: `sol-closed-team`, исходный коммит
`483e010`. Изменения подготовлены для отдельного PR в `web`; слияние и
применение на стенде Гриши не выполнялись. Этот документ подтверждает
локальные проверки, а не готовность внешнего стенда. Результат GitHub Actions
следует проверять отдельно на странице PR.

## Что изменено

- Обычный запуск требует PostgreSQL. Режим без аккаунтов разрешён только
  сочетанием `DTS_ENV=test` и `DTS_TEST_ALLOW_ANONYMOUS=true`.
- Анонимные рабочие страницы перенаправляются на вход; API, прежняя публичная
  демонстрация и скачивания закрыты. Доступны формы входа, приглашения,
  восстановления, публичный информационный лендинг `/` и необходимые статические ресурсы.
- После входа восстанавливается безопасный внутренний маршрут. Выход очищает
  клиентские данные; запоздавший запрос не возвращает данные в очищенный
  бинарный кэш. Защищённые ответы не сохраняются в HTTP-кэше браузера.
- Viewer больше не создаёт постоянные паспорта источника. Авторство новых
  данных использует существующий серверный аккаунт и проект.
- Подготовлены командная Compose-конфигурация, проверка закрытого доступа
  и SHA, обязательные PostgreSQL/Redis и резервирование перед обновлением.
  Применение этих сценариев на сервере ещё не проверено.

## Подтверждённые проверки

- Клиент: 33 теста, ESLint, TypeScript и сборка Vite.
- Сервер: итоговый полный набор `services/web-api/tests` — 133 passed,
  0 failed, 0 skipped, включая проверки шести подготовленных реальных записей.
  Использованы отдельные тестовые схемы PostgreSQL.
- Проверка соответствия OpenAPI прошла.
- Chromium: закрытие рабочих маршрутов и API, приглашение, создание пароля,
  возврат к исследованию, права viewer, выход. Вход без переполнения на
  ширинах 320, 390, 430 и 1440 px.
- Отдельный сценарий аккаунтов проверил отзыв доступа и восстановление после
  ошибки связи. Реальные аккаунты команды в QA не использовались.
- Изолированный Nginx: конфигурация корректна; `/research?record=5` без
  сессии возвращает 303 на `/login` с сохранённым маршрутом, архивный API —
  401, форма входа — 200. Редирект оставлен относительным, чтобы сохранять
  внешний HTTPS и порт обратного прокси.

## Повторный аудит авторизации и БД

Исправлены дополнительные ошибки:

- Вход теперь атомарно проверяет актуальность пароля и состояние аккаунта
  перед выдачей сессии под блокировкой строки пользователя. Одновременная
  смена пароля или отключение не оставляет сессию, созданную по старым данным.
  Argon2-проверка выполняется до блокировки; сменившийся хэш отклоняется.
  Устаревшие параметры Argon2 обновляются при успешном входе.
- Общая запись документов PostgreSQL не позволяет перезаписать документ
  другого проекта при совпадении ID. Проверка находится внутри атомарного
  SQL upsert, а удаление дополнительно ограничено проектом в самом DELETE.
- Выход и вход уведомляют соседние вкладки без передачи токенов или данных
  аккаунта. Вкладки сбрасывают кэш и перечитывают сессию; поздняя стартовая
  проверка не восстанавливает истёкший аккаунт.
- Ответы отказа доступа также получают `Cache-Control: no-store`.
  Nginx возвращает контролируемый 503 и `Retry-After: 10`, если его проверка
  авторизации не может связаться с сервисом; форма входа остаётся доступной.
- Схема входа запрещает лишние поля; OpenAPI и клиентские типы обновлены.

Подтверждение:

- Полный серверный прогон: 112 успешных проверок, три пропущенных.
  Затем отдельно прошли шесть проверок дополнительного аудита, включая
  добавленную после полного прогона проверку Secure-cookie и абсолютного срока.
- В настоящей PostgreSQL воспроизведены обе гонки входа: с заменой пароля и
  отключением аккаунта. Ни один сценарий не создал сессию по старым данным.
- Проверены изоляция документов по проекту, запись ID автора в PostgreSQL,
  хранение только хэша сессии и сохранность работы, истории и аккаунта после
  перезапуска приложения. Это не заменяет перезапуск контейнеров на стенде.
- Chromium, Firefox, WebKit прошли полный сценарий приглашения/входа,
  ограничения viewer, выхода и немедленного выхода в соседней вкладке.
  Мобильные проверки: 320/390/430 px, также 1440 px.
- Nginx проверен отдельно: анонимный API — 401, рабочая страница — 303,
  авторизованный доступ — 200; при отключённом тестовом upstream — 503
  с `no-store` и `Retry-After`, вход продолжает возвращать 200.
- 33 клиентских теста, ESLint, TypeScript/Vite, Ruff для изменённых модулей
  авторизации и тестов, проверка OpenAPI и `git diff --check` прошли.

Логика отзыва и сроков сессий сверена с
[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## Полный обход границы доступа

Дополнительный аудит охватывает приложение и реальный изолированный Nginx.
Регрессионный тест перебирает все зарегистрированные закрытые API и методы:
сейчас это 113 сочетаний. Прежние публичные API также возвращают 401.
Исключения для API — вход, принятие приглашения, восстановление по токену и два
минимальных health-маршрута; последние не выдают архив или пользовательские данные.

| Проверяемая граница | Поведение |
|---|---|
| Рабочие страницы без сессии | 303 на вход, безопасный внутренний возврат |
| API и скачивание кейса без сессии | 401, `Cache-Control: no-store` |
| Ошибочный Host | 403 до обращения к сессиям и PostgreSQL |
| Чужой Origin или `Sec-Fetch-Site: cross-site` при записи | 403 |
| Вход/активация/восстановление с формой вместо JSON | 415 |
| Неверный CSRF, включая не-ASCII заголовок | 403; нет записи и необработанного 500 |
| Replay другого аккаунта | Чтение, команды, поток и удаление — 403 |
| Открытый SSE после отзыва, простоя, отключения аккаунта или отказа БД | Выдача прекращается |
| Повторный вход в той же вкладке | Прежняя cookie-сессия отозвана; другие устройства сохраняют отдельные сессии |
| HTML, JSON, sourcemap и скрытый файл в `/assets` | 404; разрешены необходимые JS/CSS/шрифты/изображения |
| Встраивание страниц в iframe | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'` |
| Сервис авторизации недоступен за Nginx | Закрытая страница 503, `no-store`, `Retry-After: 10`; вход 200 |

Ранее replay проверял сессию только при открытии SSE и не проверял владельца.
Теперь оба типа потоков повторно проверяют действующий аккаунт, проект и роль.
Проверка не продлевает сессию фоновой выдачей событий.

Закладки сохраняют серверный ID автора; запись и удаление доступны
analyst/admin. Прежние записи без подтверждённого аккаунта не переатрибутируются.

Проверены все три браузера: Chromium, Firefox, WebKit, включая
320/390/430/1440 px, приглашение, вход, viewer и выход в соседней вкладке.
Повторный клиентский набор: 33 теста, lint, TypeScript/Vite; OpenAPI и
проверки импортов/неопределённых имён Ruff прошли.

Итоговый полный серверный прогон после обновления pytest: **133 passed,
0 failed, 0 skipped**. Переданы пути к шести подготовленным реальным записям
и проверенной очереди, поэтому три прежних пропуска также выполнены.
Дополнительно отдельно прошли 17 проверок новой границы доступа.
Проверки используют одноразовые схемы PostgreSQL и отдельные временные каталоги;
аккаунты и данные основного стенда не затрагиваются. Полный набор включает
сохранность авторства после перезапуска приложения и изолированный backup/restore.
Сам PostgreSQL-контейнер и контейнеры действующего стенда в этой работе не перезапускались.

Аудит зависимостей: `npm audit` — 0 известных уязвимостей. `pip-audit`
обнаружил CVE-2025-71176 у pytest 9.0.2 (инструмент тестирования, небезопасные
временные каталоги UNIX). В обоих requirements закреплён pytest 9.0.3;
повторный аудит полного lockfile и worker — 0 известных уязвимостей.
Проверены 45 закреплённых Python-пакетов.
Исправление подтверждено в [журнале pytest](https://docs.pytest.org/en/stable/changelog.html#pytest-9-0-3-2026-04-07).
Это проверка опубликованных зависимостей, не сканирование ОС или контейнерного образа.

Правила доступа сверены с [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
и [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
CSP здесь ограничивает iframe, base и object; полный запрет inline-script
не вводился. Эти проверки не являются гарантией отсутствия любых уязвимостей
и не заменяют независимый penetration test.

## Публичный лендинг при закрытом рабочем контуре

На `/` добавлена информационная страница с кнопкой входа и объяснением
приглашений. Она не запрашивает рабочие API и не показывает измерения,
пользовательские данные или кейсы. `/try` и прежние публичные API остаются
закрыты; исключение для корня не распространяется на `/index.html`.

Проверены переход на вход клавишей Enter, ссылка на объяснение приглашений
и отсутствие горизонтального переполнения при 320/390/430/1440 px
в Chromium, Firefox и WebKit. Полный сценарий приглашения, входа,
прав viewer и выхода в соседней вкладке сохранён и пройден во всех трёх браузерах.

Через изолированный Nginx: корень — 200, рабочий маршрут без сессии — 303,
рабочий API — 401; `nginx -t` прошёл. При отказе настроенного PostgreSQL
информационный корень остаётся доступен, вход возвращает 503, обхода
защиты данных нет. Повторный полный серверный набор: **133 passed,
0 failed, 0 skipped**; клиентские lint, TypeScript и сборка прошли.

Проверки выполнены на отдельных локальных портах 8091/8093 и временных
схемах PostgreSQL. Основной локальный стенд 8081 и сервер Гриши не обновлялись.
