# Пайплайн: сохраняемые настройки и сравнение

Журнал этого этапа. Лендинг, меню и остальные разделы не меняются. Закреплённый метод `median_x3+spatial_z_halo` и его SHA не меняются.

## Почему такое хранение

Исследование уже хранит «работу» в `documents` с видом `investigation`: проект, автор, ревизия, идемпотентность, история. Пайплайн не создаёт вторую «Работу» и не пишет в этот список, иначе черновик окна появился бы в исследовании.

Настройки пайплайна — отдельный вид документа `pipeline_setting` в той же таблице `documents`. Тот же механизм проекта, автора, ревизии и резервного копирования. Старые документы не переписываются. `backup`/`restore` уже копируют всю таблицу, поэтому новый вид попадает в снимок без второй схемы.

Связь с расчётом односторонняя. Задача хранит снимок настроек на момент отправки. Поздняя правка документа задачу не меняет.

## Контракт HTTP

Общие правила, как у существующих маршрутов: cookie-сессия, `X-Workbench-Token` на запись, проект `local`. Нет сессии — 401. Viewer читает и получает 403 на запись и на расчёт. Чужой `X-DTS-Project` отвергается. Авторство назначает сервер.

Создание `POST /api/v2/pipeline-settings`, 201, заголовок `Idempotency-Key` длиной 8–128.

```json
{
  "title": "Окно записи 6",
  "record_id": "6",
  "source_sha256": "64 hex",
  "window": {"row_start": 0, "row_end": 32, "column_start": 0, "column_end": 64},
  "point": {"row": 0, "column": 0},
  "method": "median_x3+spatial_z_halo",
  "method_version": "237168f4d4a3e11260c9f692880cc477cd7af779",
  "parameters": {},
  "run_ids": []
}
```

Сервер назначает `id`, `project_id`, `account_id`, `author_name`, `revision` 1, `created_at`, `updated_at`, `job_ids` []. Повтор того же ключа и того же тела возвращает тот же объект. Другое тело с тем же ключом — 409. Окно проверяется так же, как у задачи: полуоткрытое, внутри записи, не меньше двух столбцов, в бюджете. Точка внутри окна. Метод и версия только закреплённые. `parameters` только `{}`: у этого метода нет клиентских параметров. `run_ids` не больше двух и только результаты того же источника и SHA. Курсор отдельно не сохраняется.

`GET /api/v2/pipeline-settings` и `GET /api/v2/pipeline-settings/{id}` доступны зрителю своего проекта.

`PATCH /api/v2/pipeline-settings/{id}` передаёт `expected_revision` и только изменённые поля. Чужая ревизия — 409, тело содержит актуальную версию, запись не перетирается. `job_ids` клиент не задаёт.

`POST /api/v2/analysis-preflight` принимает то же тело, что `POST /api/v2/analysis-jobs`, плюс необязательные `settings_id` и `settings_revision`. Проверяет роль, SHA, границы, бюджет и закреплённый метод. Задачу не создаёт и место в очереди не занимает. Ответ: `accepted`, `ready`, `method`, `method_version`, `max_cells`, `timeout_s`. Предупреждение только с конкретной причиной, например worker недоступен. Успешный preflight не гарантирует следующий submit.

`POST /api/v2/analysis-jobs` по-прежнему проверяет всё сам. Если переданы `settings_id` и `settings_revision`, ревизия должна совпасть, а окно и SHA — с сохранённым документом. В задачу записывается снимок: окно, SHA, точка, метод, версия, пустые параметры и принятая ревизия. Сервер добавляет id задачи в `job_ids` и увеличивает ревизию документа. Ответ задачи содержит `settings_id`, `settings_revision` снимка и `settings_revision_after`. Редактирование документа после этого снимок не меняет.

Сравнение двух результатов делает клиент по уже сохранённым run. Общая область — пересечение полуоткрытых окон одного `record_id` и одного SHA. Пустое пересечение, другой SHA или отсутствующий слой объясняются и не подменяются. Направление разности явное. Победителя нет.

## Проверка 15.10.2026

Сохранение, устаревшая ревизия, запрет зрителю, чужой проект, пустой preflight, снимок задачи после правки черновика и резервная копия вместе с неизменным кейсом прогнаны дважды на временной схеме PostgreSQL. Клиентские проверки состояния прогнаны дважды: 15 случаев. Сборка, lint и сверка OpenAPI завершились с кодом 0.

На временной схеме выполнен ограниченный расчёт записи 6 тем же SHA, что у архива. Повтор того же ключа вернул ту же задачу. После правки названия снимок ревизии у задачи остался прежним. Второй результат с пересекающимся окном сравнён как «результат B − результат A», без победителя; значения профилей взяты у сервера.

Chromium открыл `/pipeline` на изолированном контуре: сохранение, «Проверить» без новой задачи, ограниченный расчёт, два перезагрузочных сохранения `job_id`, четыре ширины без горизонтального переполнения и сравнение двух готовых run. Firefox и WebKit этим запуском не стартовали.

Прямой адрес `/pipeline` добавлен в список страниц собранного интерфейса. Без этого перезагрузка на QA-сервере отдавала 404, хотя Vite отдавал тот же экран.

Образ на `127.0.0.1:8081` этих маршрутов не содержит: `GET /api/v2/pipeline-settings` и `POST /api/v2/analysis-preflight` отвечают 404. Живой расчёт шёл процессом из этого дерева, не из контейнера. Контейнеры команды не останавливались. Коммит и публикация не выполнялись.

## Рабочий сеанс 15.10.2026

Контейнер `haklolarp-web-api` пересоздан из этого дерева. Том, сеть и окружение сохранены. Интерфейс на `127.0.0.1:8081` и расчётный worker не перезапускались. Через `http://127.0.0.1:5173` сохранение настроек и preflight отвечают не 404. Ограниченный расчёт записи 6 дошёл до `complete`, повтор ключа вернул тот же объект, правка названия не изменила снимок задачи. Сравнение двух run на пересечении идёт как «результат B − результат A». Прежний образ сохранён локально как `haklolarp-web-api:previous`.
