# Запуск и показ DTS Workbench

10 октября 2026. Реальный архив, репетиционные ответы, существующая обработка. Подтверждённая модель Захара подключается отдельно; её веса и качество здесь не выдуманы.

Приёмка, реальные измерения и актуальные PNG: [DEMO-ACCEPTANCE.md](DEMO-ACCEPTANCE.md). По умолчанию показ использует `5.csv / review-00018`; это наблюдаемое изменение из проверенного пакета, не подтверждённая авария.

## Запустить у себя

Используйте ветку `web`, Node 24/npm, Python 3.12 и Docker Compose. Зависимости и private-конфигурация описаны в [PLATFORM.md](PLATFORM.md); нужны подготовленные исходные массивы шести CSV и пакет очереди. Исходники/очереди монтируются read-only, runtime хранится отдельно. Не используйте пароли из чужого окружения и не коммитьте `.runtime`.

```text
docker compose -p haklolarp-web --env-file .runtime/platform.env -f compose.web.yaml -f compose.platform.yaml --profile stream up -d --build --wait
```

Откройте `http://127.0.0.1:8081/demo`, войдите своим участником. Для просмотра и репетиционного ответа достаточно доступа к локальному архиву; для потокового эпизода нужны analyst/admin и сервисы Redis/ClickHouse/stream worker. Очистка профиля требует действующего `DTS_ML_URL`; подготовленный результат можно показать без работающей модели. При отсутствии зависимости интерфейс объяснит ограничение, исходник останется доступным.

## Подготовка перед выступлением

Для основного выступления используйте [показ сохранённого кейса](CASE-PRESENTATION.md): пять шагов из неизменяемого снимка, без новых расчётов и записи ответов. На странице кейса нажмите «Показать на защите». Там же описаны тайминг 4–6 минут, управление, мобильный вид и резервный HTML. Ниже описан существующий `/demo` для интерактивной репетиции — это отдельный сценарий.

Текущая сверка команды и два проверенных контекста: [DEFENSE-READINESS](DEFENSE-READINESS.md). В обычном исследовании выбирайте сохранённый расчёт явно: один видимый ID должен совпасть с `processing_run_id` скачанного JSON. Более новый расчёт не меняет выбранный. Паспорт сохраняет эту привязку. Без выбора обработанного результата экспорт содержит исходный сигнал.

### Краткий текст защиты

В обычном исследовании теперь можно зафиксировать неизменяемый кейс: [CASES](CASES.md). Для показа откройте участок, выберите расчёт, проверьте состав и сохраните кейс. Скачайте ZIP, откройте `evidence.html` без сервера. Затем измените текущий ответ или выберите более новый расчёт и покажите, что прежний кейс/ZIP сохранил первоначальные значения и ревизию. Делайте изменение ответа только в изолированном тестовом окружении; рабочий ответ не редактируйте ради сценического эффекта. Если реального ответа нет, показывайте его отсутствие — репетиционный ответ не переносится в рабочий кейс.

«Температурное поле само по себе ещё не объясняет, что произошло. Наше рабочее место связывает измерение, конкретный расчёт и независимый ответ специалиста. Мы сохраняем настоящие координаты, время и пропуски; большие записи передаются блоками. Специалист выбирает результат обработки и получает отчёт ровно с теми данными, которые видел на графике. Версия источника, метод, параметры и ID расчёта остаются проверяемыми. Чужой расчёт, изменившийся источник или новая версия результата не подменяют выбранный кейс. Для жюри есть ограниченная публичная демонстрация; рабочая проверка защищена приглашениями и ролями. Сегодня reference-обработка демонстрирует связность платформы; качество обнаружения аварий без независимого эталона мы не заявляем».

После подключения подтверждённого результата Захара заменить только предложение о reference-обработке на точное описание фактически показанного метода и его ограничений. Полный сценарий ниже занимает 4–6 минут.

1. Выберите окно реального `5.csv`, нажмите «Начать репетицию». Предпочтение по умолчанию — окно из существующей подборки `real-data-v2`; точный идентификатор и SHA видны в маршруте.
2. На первом шаге проверьте готовность. Сам обзор и точные срезы подгружаются автоматически с ограниченным кэшем; весь CSV браузеру не передаётся.
3. На шаге сравнения заранее получите обработку или подключите фактический результат. Выберите профиль, который хотите обсуждать; он сохраняется в URL.
4. Скачайте автономный HTML и JSON. HTML откройте локально без сервера — это резерв для сбоя сети. Экспорт содержит репетиционную пометку и исходный SHA.
5. Сохраните ссылку на нужный шаг. Она работает после обновления и требует того же аккаунта; передачу другому участнику обеспечивает автономный отчёт, а не доступ по знанию ID.

## Сценарий докладчика, примерно 4–6 минут

| Шаг | Что показать | Что сказать |
|---|---|---|
| Измерение | Поле, оси, покрытие, SHA | «Температура измеряется вдоль волокна. Мы сохраняем время, координаты и качество первичных данных». |
| Наблюдение | Курсор, точный профиль/ряд, соседний контекст | «Это кандидат для исследования. Проверим, где и как изменился сигнал, прежде чем делать вывод». |
| Сравнение | Общие шкалы и курсор, разность, версия метода | «Вот фактический результат обработки. Разность показывает изменение значений; сама по себе она не доказывает, что удалён шум». |
| Проверка | Ответ с обоснованием рядом с сигналом | «Человек оценивает наблюдение. Сегодня это репетиция: ответ не попадёт в рабочую разметку». |
| Отчёт | HTML/JSON, происхождение и ограничения | «Другой специалист получает исходные значения, контекст и основание вывода, а не только картинку». |

Не называйте окно подтверждённой аварией, медианный фильтр — обученным классификатором, неизвестный часовой пояс — UTC, а исторический replay — оборудованием онлайн. Если ответа или обработки нет, отчёт показывает их отсутствие.

Шаги переключаются кнопками и стрелками ←/→ вне полей/кнопок/ссылок. Клавиши в поле обоснования редактируют текст и не меняют шаг. Можно свободно вернуться назад; профиль, координата, границы и шкала источника сохраняются. На телефоне шаги расположены вертикально, сигнал и решение идут последовательно; кнопка сохранения остаётся доступной при прокрутке формы. Эмуляция ширины не заменяет проверку клавиатуры физического телефона.

## Потоковый эпизод

Раскройте блок «Потоковый эпизод». Начните техническую передачу: она получает отдельный job/replay ID и воспроизводит настоящую исходную запись.

Покажите различие «принято в Redis», «сохранено в ClickHouse», «сверено и обработано DSP». Прервите передачу собственной кнопкой, дождитесь подтверждённого `cancelled`, затем возобновите. Идентичность задания остаётся прежней. Общие сервисы не останавливаются. При потере связи страница повторяет чтение подтверждённого снимка; просмотр архива не зависит от потока.

Запущенная передача продолжается при выходе со страницы. Не запускайте несколько технических показов одновременно перед выступлением. Успешно завершённая передача этой кнопкой повторно не запускается; для нового показа создайте новую репетицию.

## Как устроена защита

Сервер устанавливает HttpOnly/SameSite cookie репетиции. Пока она активна, рабочие мутации блокируются во всех вкладках этого browser context, даже при ручной отправке действующего CSRF-токена. Обоснование сохраняется в отдельном документе `demo_answer`, обработка — в `demo_processing`, рабочий экспертный журнал и история ML-run не изменяются. Источник/очередь/границы фиксируются, сессия живёт 48 часов; после изменения версии или истечения нужно создать новую.

Чтобы вернуться к рабочему импорту, назначению или экспертному ответу, нажмите «Завершить репетицию» в общей синей полосе. Для другой роли/участника нельзя открыть чужую сессию по ID. Подключение новых результатов: [RESULT-HANDOFF.md](RESULT-HANDOFF.md).

Публичного стенда этот запуск не создаёт. Перед общим доступом команде потребуются отдельная настройка HTTPS/доступа и приёмка инфраструктуры.
