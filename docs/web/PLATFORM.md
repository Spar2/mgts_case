# DTS Workbench: локальная платформа данных и экспертизы

Обновление 10 октября 2026. Ветка `web`. Это запускаемый локальный стенд с авторизацией, постоянным хранилищем, отдельными workers и проверенной передачей реальных измерений. Подключение оборудования, подтверждённый классификатор и публичный командный стенд требуют отдельной приёмки.

[Аудит и завершённые улучшения локальной версии](LOCAL-HARDENING.md): защита промежуточных снимков lease, возобновление передачи, управление доступом, версии кэша, авторизованный CI и измерения браузера.

Новый маршрут `/demo`: [инструкция показа](PRESENTATION-GUIDE.md), [адаптер результатов](RESULT-HANDOFF.md), [цель и критерии приёмки](DEMO-GOAL.md). Репетиция отделена от рабочего журнала и блокирует рабочие мутации серверной cookie до явного завершения.

## Что открыть Захару

1. `/research` — исходное поле, профиль и временной ряд; точные значения, исходные координаты, маски и разрывы времени.
2. `/candidates` и `/demo` — исследовательские окна и короткая подборка. Это гипотезы для проверки, не положительные обучающие примеры.
3. `/review` — самостоятельный ответ из своей учётной записи. Ответ другого эксперта не раскрывает методы в вашем журнале. Конфликт двух вкладок показывает текущую ревизию и сохраняет черновик.
4. `/system` — передача реального CSV через Redis/ClickHouse, состояние каждого этапа, фоновые задачи, назначения экспертов, обсуждение и откладывание окон, участники и роли.
5. `/runs` — постоянные результаты, их методы, происхождение и ограничения. Большие результаты загружаются по явному открытию.
6. «Сохранить паспорт и ссылку» в карточке участка — сохранить источник SHA, область, профиль, шкалу, метод, параметры, ссылки на результаты и заметки. Ссылка открывает этот контекст; несовпадающая версия источника не подставляется.

Физическую причину события нельзя доказать только тепловой картой. DSP здесь является обработкой сигнала. Ответ эксперта относится к показанному окну. Автоматические обучающие метки не создаются. Работа с существующими синтетическими результатами обозначена как историческое исследование, не как измеренная точность на реальном оборудовании.

## Состав и границы

| Компонент | Ответственность | Код |
|---|---|---|
| React/Carbon | Навигация, формы, мобильный путь, роли | `apps/web/src` |
| Worker браузера | Декодирование бинарных блоков, подготовка массивов | `data.worker.ts`, `numeric.ts` |
| WebGL2/Canvas2D/uPlot | Поле, маски, точные срезы, синхронные графики | `charts.tsx` |
| FastAPI | Контракты, доступ, каталоги, срезы, управление | `services/web-api/workbench/api.py` |
| PostgreSQL | Аккаунты, членство, ревизии, задания, паспорта, аудит | `platform.py`, `accounts.py`, `pg_reviews.py` |
| Compute worker | Анализ ограниченной области, подготовка обзоров, импорт CSV | `worker.py` |
| Stream worker | Передача записи, проверка подтверждения, последовательный DSP | `streaming.py` |
| Redis/ingester/ClickHouse | Приём, подтверждение сохранения, дедупликация | `stack/backend`, `stack/ingester`, `stack/clickhouse/v2.sql` |
| Хранилище артефактов | Неизменяемые JSON по SHA; проверка при чтении | `BlobStore` в `platform.py` |

Первая конфигурация использует проект `local`. Учётные записи, журналы и операции привязаны к проекту; архив исходных шести записей принадлежит `local`. Полноценный интерфейс создания других проектов и загрузки их источников здесь не реализован. Структура членства подготовлена, межпроектные операции проверяются сервером.

`BlobStore` сейчас использует файловую систему общего Docker-тома. PostgreSQL хранит ссылки на крупные результаты. Это не готовый S3-клиент и не решение для нескольких хостов. При переходе на несколько машин нужен общий объектный backend, распределённый ограничитель входа и политика хранения артефактов.

## Первый запуск

Нужны Docker Desktop с Linux-контейнерами. Для разработки вне контейнеров — Python 3.12 и Node 24. Команды выполняются из корня этой ветки.

Создайте приватный `.runtime/platform.env` (каталог исключён из Git):

```dotenv
DTS_POSTGRES_PASSWORD=<случайная длинная строка из букв и цифр>
DTS_RECORDS=C:/path/to/prepared/records
DTS_QUEUE=C:/path/to/prepared/review-queue
DTS_RESEARCH_PACK=C:/path/to/real-data-v2
DTS_ML_URL=http://host.docker.internal:8082
DTS_IMPORT_ROOT=C:/path/to/incoming-csv
```

`DTS_RESEARCH_PACK` необязателен. Подготовленные записи содержат `manifest.json`, `raw_c.npy`, `invalid_reason.npy`, координаты, время и профили. Каталог очереди содержит `queue.json`, `manifest.json` и проверяемые NPZ. Это форматы существующих ML-наработок; файлы нельзя заменять произвольным JSON.

```powershell
docker compose -p haklolarp-web --env-file .runtime/platform.env -f compose.web.yaml -f compose.platform.yaml --profile stream up -d --build
```

Откройте `http://127.0.0.1:8081`. PostgreSQL для локальной диагностики слушает только `127.0.0.1:5434`; Redis и ClickHouse наружу не опубликованы. Не меняйте имя compose-проекта: оно определяет постоянные тома.

Создайте первого администратора; пароль вводится интерактивно, встроенного пароля нет:

```powershell
docker exec -it haklolarp-web-api python -m workbench.accounts zakhar --name "Захар"
```

Для текущего рабочего компьютера создан отдельный `local-admin`. Его данные лежат только в приватном `.runtime/local-admin.json`. Этот файл и env-файл не отправляются в GitHub. Других участников администратор создаёт в разделе «Система».

Без `--profile stream` запускаются аккаунты, API и compute worker. Для передачи CSV нужны также Redis, ClickHouse, ingester и stream-worker. В старой конфигурации только `compose.web.yaml` остаётся совместимый режим SQLite без персонального входа; это режим локальной разработки, не конфигурация общего стенда.

## Роли и независимость

| Роль | Возможности |
|---|---|
| viewer | Читать архив, результаты и сохранять паспорт своего контекста |
| expert | Самостоятельные ответы в своём журнале, чтение назначений |
| analyst | Вычисления, импорт результатов, replay, назначения и состояния окон |
| admin | Возможности эксперта и аналитика, создание участников, отключение учётных записей своего проекта |

Пароли хэшируются Argon2. Сессия — случайный отзываемый токен в HttpOnly/SameSite=Strict cookie, срок 12 часов. Мутации требуют CSRF-токен; сервер проверяет Origin и loopback Host. Отключение аккаунта отзывает сессии. Для HTTPS нужно `DTS_SECURE_COOKIES=true`; внешнюю публикацию нельзя делать простым открытием порта.

Автор журнала определяется account ID, проектом и SHA очереди. Имя в форме нельзя заменить. Старые самостоятельно заявленные имена не доказательство личности. Включение сохранения черновиков на доверенном устройстве остаётся явным выбором пользователя; ключ черновика включает account ID.

## Как именно проходят данные

```text
проверенный real CSV / mmap
    → backend: validate + source SHA + native row + segment
    → Redis: публикация, backpressure, без обрезки непотреблённых записей
    → ingester: RowBinary Float64, INSERT
    → ClickHouse: FINAL logical identity (replay_id, row_idx)
    → проверка каждой сохранённой ячейки и оси против исходного массива
    → последовательный median_x3 DSP каждого подтверждённого профиля
    → PostgreSQL snapshot + SSE notification
    → браузер запрашивает бинарное поле отдельно
```

«Принято» означает публикацию в Redis. «Сохранено» означает непрерывный диапазон строк в ClickHouse. «DSP» означает действительно последовательно проверенные и обработанные строки. Поле в «Системе» берётся из исходного архива только до `verified_persisted`: соответствие этих данных ClickHouse уже проверено. Это не второй неподтверждённый источник потока.

Причины невалидности, исходная строка времени, неизвестный часовой пояс и нативный сегмент сохраняются. Неизвестный timezone не становится UTC. При повторе после отказа используется тот же replay ID и абсолютный индекс строки; транспортная сессия не меняет идентичность измерения.

Обнаружена и исправлена реальная проблема JSON-вставки в ClickHouse 24: часть координат менялась на последний бит Float64. Нативные профили теперь вставляются в RowBinary; при проверке координаты и температуры читаются через битовое представление. Температурные поля для экрана передаются Float32, точные срезы и первичные массивы остаются Float64. Формат RowBinary: [официальная документация ClickHouse](https://clickhouse.com/docs/interfaces/formats/RowBinary).

Дедупликация логическая (`ReplacingMergeTree` + `FINAL`), не обещание физически единственной строки на диске. Содержательно отличающийся повтор помещается в `profile_conflicts`. Текущий compose запускает **один ingester**; горизонтальная запись несколькими ingesters потребует атомарного общего реестра идентичности до INSERT.

## Бинарные блоки и быстродействие

- Максимальный блок — 256 × 256, JSON содержит только метаданные.
- v1 сохраняет совместимость. `format_version=2` разделяет native quality mask и display flags: отсутствие наблюдения в бине и разрыв непрерывности не становятся одним native-кодом `8`.
- Обзоры используют физические бины и медиану валидных значений; близкий масштаб показывает реальные ячейки.
- Сначала ограничивается диапазон нативных строк, затем добавляются null-разрывы линии. Разрыв не сдвигает индекс выбранного профиля.
- ETag и SHA источника определяют версию блока. Устаревшие запросы отменяются.
- Вычислительные locks раздельны для разных cache keys. Межпроцессный lock защищает только чтение, публикацию и вытеснение файлов.
- Кэш блоков: 64 MiB desktop / 32 MiB mobile; дисковый tile-cache — 256 MiB. GPU-буферы и текстуры считаются отдельно (`__dtsGraphicsStats`), кэш — `__dtsCacheStats`.
- Очередь проверки виртуализирована; задачи, назначения и запуски показываются страницами. Списки результатов не загружают полные числовые массивы.
- «Подготовить обзоры» выполняется отдельным worker и готовит масштабы 64/128/256 и короткую исследовательскую подборку. При первом импорте источник проверяется; последующие запуски не повторяют неизменённую адаптацию пакета.

## Вычисления и ML

Задания имеют lease 30 с, heartbeat каждые 5 с, владельца и не более трёх попыток. Захват использует PostgreSQL `FOR UPDATE SKIP LOCKED`. Старый worker не может опубликовать результат после перехвата lease. Отмена сохраняется; результат отменённого задания отбрасывается. Создание field-job и его метаданных атомарно. HTTP field request ограничен 1 млн исходных ячеек, ответ ML — 8 MiB.

Проверка действующего lease защищает также промежуточные снимки; завершение field-job и ссылка на результат сохраняются одной транзакцией. Ошибочный или отменённый replay можно явно возобновить в «Системе» с тем же replay ID и SHA, с места непрерывного сохранённого диапазона. Такое действие даёт ещё до трёх попыток, сохраняет историю и не создаёт новую запись источника. Успешное задание этой кнопкой не перезапускается.

ML API подключается сервером. Токены оборудования и доступ к хранилищам не передаются браузеру. Существующая очистка профиля вызывается явно; тяжёлый анализ поля выполняется compute worker. Версия реализации ML и качество обученного классификатора не выдумываются: если сервис их не поставляет, это обозначено в результате. Подготовленные результаты можно импортировать через существующий `/api/v1/results`, сохранив SHA, метод, параметры, происхождение и ограничения.

Разногласие методов в «Системе» — доля различающихся решений в валидных ячейках исторической очереди. Это приоритет исследования, **не откалиброванная вероятность ошибки**. Раздел доступен аналитику/администратору; он не раскрывает методы эксперту до самостоятельного ответа.

## Импорт, архив и восстановление

Worker может импортировать CSV из настроенного `DTS_IMPORT_ROOT` через `/api/v2/jobs` с `kind=import_csv` и относительным `filename`. Выход за каталог запрещён; после завершения каталог API обновляется. Произвольный upload через браузер пока не реализован. Конфликт названия источника требует отдельного решения, существующая запись не перезаписывается.

Архивирование прежнего SQLite:

```powershell
docker exec haklolarp-web-api python -m workbench.maintenance migrate-sqlite /runtime
```

Операция сохраняет исходные SQLite-снимки с SHA и переносит документы идемпотентно. Старые незавершённые расчёты становятся interrupted. Старые экспертные/агентские журналы сохраняются как архив без присвоения аккаунту. Оригинальные SQLite остаются на месте. Для текущего стенда перенос выполнен.

Приватная резервная копия PostgreSQL и связанных immutable blobs:

```powershell
docker exec haklolarp-web-api python -m workbench.maintenance backup /runtime/backups/my-snapshot
```

Копия использует согласованный снимок, проверяемый manifest и содержит хэши паролей: храните её приватно. Для восстановления остановите API/workers и направьте `DTS_DATABASE_URL` и `DTS_RUNTIME` на **новую пустую БД и каталог**:

```text
python -m workbench.maintenance restore /path/to/snapshot
```

Результаты, пользователи, членство и ревизии восстанавливаются. Сессии не восстанавливаются. Активные задания помечаются failed и требуют явной повторной постановки. Команда отказывается восстанавливать поверх существующих пользователей/документов. Исходные CSV/NPY и ClickHouse нужно резервировать отдельно: эта копия сохраняет control plane и его артефакты.

## Приёмка и оставшиеся границы

[Измерения](platform/measurements.json): шесть записей, 6 749 профилей, **23 329 363** температурных значения; координаты, маски, время и сегменты сопоставлены с исходными данными. Серверный прогон 30 минут: десять сессий, 1 480 запросов, ноль ошибок, p95 тёплого блока **87,8 мс**. API 95,7→101,1 MiB; stream-worker 90,6→93,3 MiB; рост вышел на плато. Прогон выполнен 9 октября, до последней сборки 10 октября; это серверный тест на Docker Desktop/loopback, не измерение FPS или памяти физического телефона.

Браузерный путь проверен в Chromium, Firefox и WebKit: сохранение/повторное открытие паспорта, автор аккаунта, сетевой отказ, конфликт двух вкладок, назначение окна, размеры 320/390/430/1024/1440 px. Отдельно проверены потеря WebGL-контекста, Canvas fallback и клавиатура. Технические ответы пишутся только на изолированном сервере с `DTS_QA_MODE=isolated` и отдельной PostgreSQL-схемой.

Серверные тесты покрывают реальные шесть записей, native gap/ROI, форматы v1/v2, ETag, lease, отмену, повтор, роли, чужой проект, ревизии, миграцию и восстановление. CI поднимает PostgreSQL, а не заменяет её mock-объектом. Контрактные искусственные fixtures используются для проверки ПО, не для обучения ML.

Последняя локальная проверка: 26 серверных тестов и 6 клиентских тестов прошли; TypeScript, ESLint, Ruff и production-сборка прошли. `scripts/check-stream-recovery.py` проверяет настоящий отказ Redis (HTTP 503), повтор без продвижения индекса, остановленный ingester (принято 2, сохранено 0), восстановление (сохранено 2), повторную доставку (по-прежнему 2 логических профиля). Скрипт временно останавливает только Redis и ingester проекта `haklolarp-web`, восстанавливает их через `finally` и создаёт технический replay UUID; запускайте его на локальном стенде без активной работы команды. Это не проверка всех возможных аварий инфраструктуры.

Health: `/api/v2/health/live` и `/api/v2/health/ready`. Ready проверяет PostgreSQL и compute heartbeat. Авторизованный `/api/v2/status` отдельно проверяет workers, приёмник/Redis и ClickHouse; отсутствие потоковых сервисов не означает потерю архива. Результат probe кэшируется на 5 с, запросы ограничены timeout. Структурированные логи не содержат cookie, тел запросов или query strings. `OTEL_EXPORTER_OTLP_ENDPOINT` подключает экспорт trace к вашему collector; collector в этой конфигурации не установлен. Логи контейнеров ограничены 3×10 MiB.

До внешней командной эксплуатации остаются обязательные работы: TLS/реальный домен и соответствующий allowlist, общий limiter, политика длительного хранения артефактов, S3/несколько хостов при необходимости, пользовательские проекты/источники, проверка настоящего оборудования, подтверждённая ML-модель с паспортом версии, нагрузочные измерения на целевых устройствах и тесты всех сценариев отказа инфраструктуры. Целевые 60/30 FPS, <=100 мс локального действия и <=1,5 с полезного поля не объявлены достигнутыми без отдельных измерений.

Существующий `ops/deploy-web.sh` расширен опциональными `DTS_PLATFORM_ENABLED`/`DTS_STREAM_ENABLED`. Имена workflow/concurrency сохранены; push запускает проверки. Внешний деплой в рамках этой работы не выполнялся.
