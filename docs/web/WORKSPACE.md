# Единый DTS Workbench

Рабочий маршрут: **измерение → работа → конкретный результат → независимый ответ → неизменяемый кейс → ZIP**. Основная навигация: «Работы», «Архив», «Мониторинг», «Лаборатория», «Кейсы». Старые ссылки `/research`, `/analysis`, `/review`, `/runs`, `/system`, `/demo` сохранены.

## Участнику

1. Войдите своим аккаунтом. Откройте запись в архиве, готовый результат в лаборатории, карточку кандидата или подтверждённый участок мониторинга. Нажмите «Начать работу» и задайте название.
2. Работа закрепляет запись и SHA. Во вкладке «Сигнал» выберите окно, профиль, точку и слой. Наведение меняет только курсор. Нажмите «Сохранить контекст»: обновление страницы восстановит именно этот контекст и заметки.
3. Выберите конкретный запуск. При сохранении изменённого окна несовместимый результат сбрасывается с объяснением; другой не подставляется. Во вкладке «Сравнение» используйте максимум два результата одного исходника, покрывающих всё окно.
4. Во вкладке «Проверка» назначьте действующего эксперта. Задание получает отдельный неизменяемый снимок исходных значений, масок, координат и очереди. Последующая правка работы его не меняет.
5. Эксперт открывает входящие задания из меню «Другое → Экспертная проверка». До самостоятельного ответа методы и причины отбора скрыты. В коротком режиме доступны явное сохранение и переход дальше. Пояснение необязательно. Клавиши 1–4 выбирают ответ, Ctrl+Enter сохраняет, если фокус не в текстовом поле. «Пропустить» сохраняет прогресс отдельно от ответа «неизвестно».
6. После ответа эксперт может зафиксировать кейс назначенного окна и своей ревизии. Analyst/admin видит ответ назначенного эксперта и ссылку на кейс в работе. Предпросмотр показывает источник, выбранный запуск и включённую ревизию. Без ответа выводится явное отсутствие проверки.
7. Скачайте ZIP со страницы кейса. HTML открывается без сервера. JSON и manifest позволяют численно сверить значения и целостность файлов. Новые расчёты, правки работы и ответы не меняют ранее сохранённый кейс. SHA относительно manifest не доказывает авторство.

При конфликте ревизии перечитайте актуальное состояние: чужие изменения не перезаписываются автоматически. После неопределённого сетевого исхода повторите ту же попытку. Если кейс сохранён, но ссылка не добавлена, повторяется только добавление ссылки. Эти действия не создают обучающих меток.

## Лаборатория

`/laboratory` объединяет сохранённые результаты и исследовательские отчёты. Выберите два совместимых запуска: сайт вычислит общую область. Открытие сравнения передаёт оба ID и точные границы в исследование. Температуры используют общую шкалу, разность — симметричную. Необязательные слои видны только при наличии.

Real-only отчёт закреплён за `ml:1c09476310bbad92cd832dc65cf339aab3bc8e61`: 18 реальных окон, Ridge и исследовательские альтернативы, отдельные временной эксперимент и состояние классификации. Отчёт проверяется по SHA. Исторический `237168f` сохранён отдельно со старым протоколом. Noisy-target MSE, изменение сигнала, доля выделенных ячеек и экспертные ответы — разные показатели. Без независимого эталона точность обнаружения **не оценена**. Рабочий метод автоматически не меняется.

## Мониторинг

Первый источник — **воспроизведение записи**, не оборудование. `/monitoring` показывает стадии отдельно: принято Redis, записано ClickHouse, сверено с исходником, выполнен DSP профиля. Число профилей — индекс + 1. `median_x3` последнего профиля не означает анализ всего поля.

Поле доступно после подтверждения записи и числовой сверки. Запуск анализа подтверждённого интервала — явное действие. Последний совместимый результат подписан своей областью: новые поступления не продлевают его покрытие. Из него создаётся работа с ID потока и конкретным run_id. Кандидаты остаются гипотезами.

При разрыве SSE сохраняется последнее поле, показываются связь и возраст. После восстановления загружается актуальный снимок. Это не гарантия поступления оборудования: в этом этапе источник только replay.

## Права

| Роль | Возможности |
|---|---|
| viewer | Чтение архива, результатов, работ и доступных кейсов; без создания и расчётов |
| analyst | Создание/изменение работ, расчёты, назначения, чтение зафиксированного ответа и создание кейса |
| expert | Независимый ответ и прогресс; кейс своего ответа и добавление его ссылки в работу |
| admin | Возможности analyst, управление доступом, операторские действия |

Другой эксперт до собственного ответа не получает чужое заключение через кейс. Проект и SHA проверяются сервером для ссылок. Ни одно действие не создаёт `training_target`.

## Оператору

Установка и доступ: [README](README.md), [операторская инструкция](PRODUCTION-OPERATOR.md). Числовые результаты: [ANALYSIS-CONTRACT](ANALYSIS-CONTRACT.md). Секреты задаются приватной конфигурацией.

`compose.platform.yaml` добавляет управляемый `ml-compat` (loopback 8082), API, compute-worker и, с профилем `stream`, replay-worker/Redis/ClickHouse/ingester. ML совместимость закреплена `237168f4d4a3e11260c9f692880cc477cd7af779`, NumPy 2.4.3 / SciPy 1.18.1. Нейросети и обучение этот сервис не запускает. `/api/v2/service-capabilities` показывает доступность, версию и readiness. Отказ ML отключает действие, сохраняя архив и импортированные результаты. Compute-worker проверяется отдельно.

Подготовленные 36 карточек импортируются отдельно от старых очередей:

```powershell
python scripts/review-package.py --directory C:/path/to/review-queue --records C:/path/to/records --project local --author ACCOUNT_ID --title "36 реальных окон — вопросы эксперту"
```

Перед запуском задайте `DTS_DATABASE_URL` и `DTS_RUNTIME` приватно. Автор — действующий analyst/admin проекта. Проверяются SHA файлов, native координаты, время, значения, маски и типы. Повтор идентичного пакета возвращает прежний ID. Импорт карточек не импортирует человеческие ответы.

Не удаляйте runtime: он содержит неизменяемые массивы и снимки. Backup документов включает работы, события, идемпотентность, задания, прогресс и ссылки; бинарное расширение включает `analysis_run` и `review_package`. Восстановление — только в **новой пустой БД**, сессии не активируются.

## API

| Маршрут | Назначение |
|---|---|
| `GET/POST /api/v2/investigations` | Каталог и создание с обязательным Idempotency-Key |
| `GET/PATCH /api/v2/investigations/{id}` | Контекст; изменение с expected_revision |
| `GET /api/v2/investigations/{id}/history` | Автор, ревизия, действие |
| `GET/POST /api/v2/investigations/{id}/review-requests` | Неизменяемое задание; ключ и ревизия |
| `POST /api/v2/investigations/{id}/cases` | Ссылка на совместимый существующий кейс |
| `GET /api/v2/review-inbox` | Собственные входящие задания эксперта |
| `GET/POST /api/v2/review-progress` | Отдельный прогресс пропусков |
| `GET /api/v2/research-studies[/{id}]` | Закреплённые отчёты |
| `GET /api/v2/streams` | Каталог потоков проекта |
| `GET /api/v2/stream/{id}/profile?snapshot_version=N` | Подтверждённый профиль; 409 при смене версии |
| `GET /api/v2/service-capabilities` | Безопасное состояние сервисов |

Полная схема — `services/web-api/openapi.json`. Старые API сохраняются. Матрицы не помещаются в React-state: данные идут блоками через worker. Одна активная задача пользователя, две выполняемые, десять ожидающих; перегрузка — 429 с Retry-After.
