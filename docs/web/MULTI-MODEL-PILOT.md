## Почему Sol должен перепроверять модели

| Вывод модели | Решение после проверки |
|---|---|
| Muse: лимит файла 240 KiB против HTTP 256 KiB — высокий дефект | Отклонён: в документации явно различаются файл и тело запроса; запас не нарушает научный контракт |
| Muse: заполненные автором пропуски в сохранённом результате — высокий дефект | Не подтверждён: исходный результат хранится с происхождением; отображение маскирует исходную невалидность. Требуется ясная подпись экспорта, а не уничтожение авторского результата |
| Muse: `NaN` детектора попадёт в blob | Отклонён: `json.dumps(..., allow_nan=False)` выдаёт отказ. Проверка семантической схемы детектора — отдельная реальная задача |
| Обе модели: обычный отчёт выбирает первый подходящий run | Подтверждена механика; SHA/статус исправлены. Явный `run_id` для обычного исследования остаётся задачей, особенно для конкурирующих расчётов одного метода |
| Grok: `/demo` не проверяет SHA | Отклонён: проверка есть в `compatible`, строка 213, вне начала первого сокращённого фрагмента. Новый генератор включает её целиком |
| Grok: `result_ref` не загружается при `workspace.get` | Отклонён: PostgreSQL workspace вызывает `hydrate`, который загружает blob. В пакет reviewer добавлена реализация адаптера |
| Модели: ответ `/detect/field` проверяется только как конечный JSON-объект | Подтверждено чтением. Схему и семантику осей надо согласовать с действующим ML Захара; придумывать новый ответ без него нельзя |
| Muse: лимит 32 MiB удаляет старые результаты | Относится к локальному SQLite workspace. Нельзя переносить вывод на PostgreSQL+blobs; потерю/истечение результата стоит показывать явно |

Итог: схема работает на контролируемом цикле чтение → предложение diff → независимая проверка → тест. Модели ошибаются даже при уверенной формулировке «подтверждено». Для reviewer нужны полные guards и реализации адаптеров, а не только вызывающий endpoint.

## Следующее полезное поручение

Получить настоящий результат/версию ML Захара, сверить контракт `/detect/field`, оси и происхождение; затем отдельно проработать явный выбор `run_id` в обычном исследовании. Публичное демо и `/demo` не должны выдавать придуманную точность или результаты недоступного runtime. Настройка внешнего HTTPS-стенда и презентация сохраняют приоритет хакатона.
