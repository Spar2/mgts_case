# Надёжный локальный исследовательский продукт: аудит и приёмка

Аудит начат 10 октября 2026. Рабочая ветка `web`, локальный стенд 8081.

Выбранные по аудиту локальные пробелы устранены. Внешние зависимости перечислены ниже и не объявлены готовыми.

Критерии завершения этого этапа:

- Промежуточные документы и конечный результат публикует только действующий владелец lease. Потерявший lease worker не изменяет подтверждённый снимок.
- Прерванную передачу можно явно возобновить с той же идентичностью измерения; завершённые задачи не запускаются случайно повторно.
- Управление участниками имеет понятные ошибки дубликата, состояния отправки и отключения доступа. Пароли и данные сессий не попадают в аудит/артефакты проверки.
- На временную недоступность сервера интерфейс отвечает восстановлением связи, а не ложным сообщением о неправильном пароле. Сетевые и графические ресурсы освобождаются при выходе.
- Авторизованный экспертный путь проверяется воспроизводимо на отдельной схеме PostgreSQL, в том числе в CI. Производительность загрузки и ресурсы браузера измерены с указанными условиями.
- Документы отражают фактическую версию метода, состояние сервисов и оставшиеся ограничения. Локальный стенд обновлён, изменения сохранены в Git.

Внешние зависимости: публичный TLS/домен, подключение оборудования, подтверждённые модели Захара и измерения на физических телефонах. Они не подменяются локальными тестами. Контрактные fixtures служат проверке программы, не обучению модели или экспертной разметке реальных данных.

## Что изменилось

Публикация изменяемого снимка проверяет владельца действующего lease и блокирует строку задания в той же PostgreSQL-транзакции. Просроченный worker не может обновить снимок или продлить lease задним числом. Каждый захват получает отдельную owner-идентичность. Завершение field-job и публикация ссылки на его результат теперь атомарны; отменённый результат не публикуется. Heartbeat-файлы заменяются атомарно.

«Возобновить передачу» доступно аналитику/администратору для ошибочных и отменённых replay. Сервер сохраняет исходные job/replay ID и source SHA; читает непрерывный подтверждённый диапазон ClickHouse и сверяет ещё не обработанные строки до отправки следующих. Прогресс учитывает INSERT, который мог произойти до последнего сохранённого снимка. Успешное задание не перезапускается этой кнопкой. Повтор неподтверждённого создания задачи из UI сохраняет ключ идемпотентности.

Аккаунты имеют понятную ошибку занятого логина, состояния отправки, отключения и восстановления доступа с подтверждением. Отключение отзывает сессии; включение не восстанавливает старую cookie. Нельзя отключить себя или оставить проект без действующего администратора. Архивные очереди через v2 также недоступны чужому проекту. Наблюдатель и аналитик видят объяснение отсутствия права сохранить экспертный ответ.

При недоступном сервере стартовый экран предлагает повторное подключение. Выход и истечение сессии очищают числовой кэш. Поток показывает потерю связи, повторное подключение и последний подтверждённый снимок. Статус проверяет настоящий backend/Redis/ClickHouse и heartbeat workers; недоступную передачу нельзя запустить из UI. Выбранный метод в паспорте больше не объявляется доказательством версии выполненной реализации.

Кэш браузера и URL HTTP-кэша включают SHA источника или очереди. При несовпадающем SHA график записи не рисует присланный блок. Сервер отклоняет устаревшие SHA записи/очереди ответом 409. Точные срезы и ключи запросов также привязаны к версии источника. Это устраняет повторное использование старой матрицы, когда область/название совпали, а версия данных изменилась.

## Доказательства

- 26 серверных тестов на PostgreSQL и всех шести исходных записях; 6 клиентских тестов. TypeScript, ESLint, Ruff и production-сборка проходят.
- Управление доступом, мобильный вход, дубликат логина и восстановление связи пройдены в Chromium, Firefox и WebKit. Новые технические аккаунты существуют только в отдельной QA-схеме.
- Сохранение паспорта, независимый ответ, сетевой отказ, конфликт вкладок и назначение окна пройдены с реальными записями и отдельно на контрактных CI-fixtures.
- Реальный `4.csv`: отмена после 13 принятых профилей, возобновление с прежней идентичностью, завершены все 708 профилей, сверены 1 197 228 ячеек. [Результат](platform/stream-resume-2026-10-10.json).
- [Итоговые измерения браузера](platform/browser-measurements-2026-10-10.json): первый полезный обзор 1043 мс при 1440 px, 816 мс при 390 px. p95 повторного переключения с прогретым версионным кэшем — 50 и 47 мс. После ухода с графиков активных workers, WebGL-контекстов, буферов и текстур — ноль. Серверные/браузерные кэши ограничены, числовой кэш занимает около 1,5/0,8 MB в этом прогоне. Это headless desktop и эмуляция ширины, не телефон, не SLA и не измерение 60 FPS. При первом запросе новых обзоров переключение медленнее; полный набор измерений сохранён.

## Как повторить браузерную проверку

Из корня ветки, после сборки `apps/web`, установите приватный `DTS_TEST_PG_URL` на отдельный локальный PostgreSQL. Сценарий создаёт собственную временную схему, а не использует журнал команды.

```text
python scripts/platform-qa.py serve --records /path/to/prepared/records --queue /path/to/queue --pack /path/to/real-data-v2
```

Для контрактных fixtures `--pack` не нужен. Сервер слушает 8091. В `.runtime/auth-qa/browser-auth.json` появится приватная cookie тестового аккаунта; никогда не загружайте этот файл в Git или CI-артефакты.

```text
playwright-cli --session auth-qa open http://127.0.0.1:8091/system --config=scripts/playwright-ci.json
playwright-cli --session auth-qa state-load .runtime/auth-qa/browser-auth.json
playwright-cli --session auth-qa goto http://127.0.0.1:8091/system
playwright-cli --session auth-qa run-code --filename=scripts/qa-platform.js
playwright-cli --session auth-qa run-code --filename=scripts/qa-account-journey.js
playwright-cli --session auth-qa run-code --filename=scripts/qa-browser-performance.js
playwright-cli --session auth-qa close
```

Установку браузеров CLI выполняйте по инструкции Playwright. После остановки своего QA-сервера: `python scripts/platform-qa.py drop` удаляет только схему, записанную в его приватном state.json. CI теперь включает такой авторизованный путь после прежних проверок SQLite. Команды пройдены локально на реальных данных и CI-fixtures; запуск GitHub Actions после публикации — отдельный внешний результат, который здесь не выдуман.

`scripts/check-stream-resume.py` проверяет реальный поток на 8081 с приватным локальным администратором; создаёт отдельное техническое задание, не экспертную разметку. Запускайте без активной командной работы. Исходные данные, журналы и тома не удаляются.
