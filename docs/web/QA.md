# Проверки локального DTS Workbench

Историческая приёмка 9 октября 2026 первого локального пути. Текущая платформа: [PLATFORM.md](PLATFORM.md), аудит 10 октября: [LOCAL-HARDENING.md](LOCAL-HARDENING.md), объём новой демонстрационной цели: [DEMO-GOAL.md](DEMO-GOAL.md). Ниже сохраняются условия прежних измерений; они не доказывают приёмку последующих изменений.

Контрактные проверки охватывают sentinel `-300`, нечисловые наблюдения, нерегулярные координаты, разрыв времени, физическую медианную агрегацию, нативные блоки при приближении и точные срезы всех шести записей. Время без известного часового пояса не превращается в UTC. Исходные float64 остаются в массиве и точных срезах; поле передаётся float32.

## Что прошло

- Клиент: 5 тестов Vitest, ESLint, TypeScript и production build. Проверяются двоичный пакет, пропуски и экстремумы при прореживании, бюджет LRU, повтор с обновлённым локальным токеном без изменения ключа идемпотентности и отсутствие автоматического повтора неопределённой сетевой записи.
- Сервер: 8 тестов pytest, включая настоящие массивы. SQLite сохраняет ответы после открытия нового экземпляра журнала; конкурентные запросы с одним ключом не создают дополнительные ревизии. Повтор ключа с другим телом и конфликт ревизий отклоняются. Проверены Host/Origin/token, размер тела, ограничения replay/ML и отказ при слишком большом ответе ML.
- OpenAPI соответствует сохранённой схеме; TypeScript-типы сгенерированы из неё.
- Chromium, Firefox и WebKit: каталог шести записей, подтверждённый точный профиль, самостоятельная проверка, закрытые методы до ответа, разворачивание поля/Escape, reduced motion и размеры 320, 390, 430, 1024 и 1440 px без горизонтального переполнения после завершения resize.
- Нативное приближение реального `5.csv` дополнительно проверено в Firefox 156 и WebKit: участок вокруг профиля 1700 / 300 м показывает 3 599 исходных валидных наблюдений без ошибок. [Отчёт](measurements/native-zoom-browsers.json).
- Chromium: потеря WebGL-контекста и изначально недоступный WebGL переключают график на Canvas2D. Старые WebGL-ресурсы освобождаются. Управление вариантом ответа клавиатурой работает.
- Replay: play/pause, скорость, переход к точному профилю, удаление сессии и её восстановление, удаление старой сессии после выбора другого источника.
- Задержанные старые GET поля и среза при смене записи отменяются; их поздние ответы не меняют SHA, шкалу и точное наблюдение новой записи. Сценарий `qa-request-races.js` включён в CI.
- В отдельном помеченном QA-журнале: отказ сети сохраняет черновик; повторное сохранение подтверждается; две вкладки дают 409 и сохраняют второй черновик; новая ревизия переживает обновление страницы. После ответа доступны 11 подготовленных методов и совместимый экспорт.
- Настоящий процесс uvicorn QA-сервера остановлен и поднят заново с тем же SQLite-журналом. Предыдущий ответ сохранился; открытая страница без reload получила один отказ старого токена, обновила токен и успешно сохранила следующую ревизию. [Отчёт](measurements/server-restart.json). Сценарий `qa-server-restart.js` запускается дважды вокруг ручного перезапуска **только изолированного QA API**.
- Реальный CPU ML API: очистка 2 364 точек профиля `5.csv`; фоновый анализ ограниченного окна завершён. Также проверен вызов очистки из Docker через серверный gateway. Нового обучения и новых весов нет.
- Собраны оба Docker-образа; Compose на `127.0.0.1:8081` прошёл healthcheck. Рабочий журнал этого стенда не использовался для технических QA-ответов.

Браузер WebKit в Playwright не заменяет испытания Safari на настоящем iPhone. Проверка мобильной геометрии выполнена на компьютере; скорость и энергопотребление телефона ещё не измерены.

## Измерения API

Условия: Windows, Python 3.12, loopback HTTP, последовательные GET, gzip; параллельно могли работать replay и браузерный QA. Размер обзора 190 × 127. У каждого источника измерены первый запрос и 10 повторов. Первый запрос мог использовать ранее заполненный дисковый кэш: это не обещание времени холодного запуска.

| Показатель | Наблюдавшийся диапазон |
|---|---:|
| Первый запрос обзора | 538–1 079 мс |
| Медиана повторов обзора | 5,86–9,13 мс |
| Максимум среди повторов каждого источника | 14,53–21,72 мс |
| Обзор после распаковки | около 224 KB |
| Обзор по Content-Length с gzip | 48–87 KB |
| Точный профиль + временной ряд | 10,09–39,93 мс |

Полный отчёт: [api-loopback.json](measurements/api-loopback.json). Это время получения API-ответа, а не INP интерфейса и не время отрисовки.

Отдельно измерены 30 настоящих кликов «Следующий профиль» в Chromium 154 на компьютере, через Docker loopback, 1438 × 1168 px / DPR 1. Event Timing зарегистрировал 20 click-событий от порога 16 мс: длительности 16–24 мс, события ниже порога не входят в отчёт. Это хороший результат для данного действия в данных условиях, но не полноценный INP всей сессии. [Исходный отчёт](measurements/interaction-timing.json), воспроизведение — `scripts/qa-interaction-timing.js`.

## Длительный replay

Компьютер: Windows, 24 физических / 32 логических ядра, CPU сообщает имя `Genuine Intel(R) 0000`, RAM 68 002 148 352 байта (около 63,3 GiB). Это мощный рабочий компьютер; переносить его результаты на телефон нельзя.

Финальный замер **полностью завершён**: 13:07:33–13:37:33 UTC, 1 800 секунд, 122 снимка. Условия: Chromium 154 на Windows, Docker loopback 8081, 1440 × 900 CSS px, DPR 1, источник `5.csv`, скорость 60× с повтором записи после конца. Параллельно проходили другие браузерные проверки и Linux CI. Сборка — `index-DMmd5MNs.js`, код приложения — коммит `6f4609e`. [Полный отчёт](measurements/replay-final.json).

| Показатель | Результат |
|---|---:|
| JS heap, минимум–максимум | 7,79–14,67 MiB |
| Медиана JS heap, минуты 2–10 / последние 10 минут | 11,87 / 12,13 MiB |
| Бинарный кэш | постоянные 0,216 MiB |
| Canvas / WebGL-контексты | постоянные 3 / 1 |
| Запрошенные WebGL vertex buffers | постоянные 589 856 байт |
| Palette texture | постоянные 1 024 байта |
| Оценка поверхностей Canvas | постоянные 2 038 880 байт |
| Ошибки replay / runtime | 0 / 0 |
| Long Tasks ≥50 мс, зарегистрированные в вкладке | 0 |
| p95 интервала requestAnimationFrame в последнем кольце кадров | 8,3 мс |

Кэш и графические ресурсы вышли на плато. JS heap колебался после сборки мусора; существенного роста между указанными окнами не наблюдается. Этот сценарий не перебирает сотни участков и не доказывает стабильность всех будущих нагрузок.

Бюджет LRU — 64 MiB при широкой первоначальной загрузке и 32 MiB при мобильной. Изменение ширины уже открытой страницы не меняет бюджет; для проверки мобильного бюджета страницу загружают заново.

Свежая мобильная загрузка дополнительно проверена при 360 × 732 px / DPR 3: бюджет 32 MiB, три Canvas, один WebGL-контекст, горизонтального переполнения нет. [Отчёт](measurements/mobile-budget.json). Это эмуляция Pixel/Android на компьютере, а не замер телефона.

Счётчики GPU включают запрошенные WebGL vertex buffers и palette texture; поверхность Canvas оценивается как ширина × высота × 4. Эти оценки не включают память драйвера, compositor и дополнительные буферы браузера. `performance.memory` Chromium — оценка JS heap, а не полная память процесса. Интервалы requestAnimationFrame характеризуют работу планировщика; они не доказывают FPS отрисовки поля или выполнение цели INP ≤100 мс.

Предварительный полный 30-минутный замер Docker-сборки находится в [replay-container-baseline.json](measurements/replay-container-baseline.json). После завершения этого замера обнаружена ошибка самого QA-скрипта: последний уже запланированный callback читал удалённое кольцо кадров. Скрипт исправлен до финального замера. Предварительная сборка также предшествует последним улучшениям нативного приближения и графической диагностике; её результаты не подменяют проверку финальной версии.

## Воспроизвести проверки

Команды сборки, контрактных тестов и проверки схемы приведены в [README](README.md). Для проверки настоящих массивов перед pytest задайте `DTS_REAL_RECORDS`.

Для браузерного QA используйте Playwright CLI 0.1.22. Сначала откройте работающий локальный стенд, затем запускайте функции:

```powershell
npx --yes --package @playwright/cli@0.1.22 playwright-cli install-browser chromium --with-deps
npx --yes --package @playwright/cli@0.1.22 playwright-cli --session qa open http://127.0.0.1:8091/research --config=scripts/playwright-ci.json
npx --yes --package @playwright/cli@0.1.22 playwright-cli --session qa run-code --filename=scripts/qa-browser.js
npx --yes --package @playwright/cli@0.1.22 playwright-cli --session qa run-code --filename=scripts/qa-replay-controls.js
npx --yes --package @playwright/cli@0.1.22 playwright-cli --session qa run-code --filename=scripts/qa-graphics.js
```

`qa-review-save.js` **пишет технические ревизии** и допускает только отдельный журнал на порту 8091 с заранее созданным маркером `QA ONLY — отдельный тестовый журнал`. На рабочем журнале этот сценарий не запускайте.

`scripts/prepare-ci-fixtures.py` создаёт такой отдельный набор в новой `.runtime/ci-smoke`: шесть маленьких CSV для проверки контрактов, массивы, очередь без методов и помеченный технический журнал. Скрипт отказывается перезаписывать существующую папку. Задайте `DTS_RECORDS`, `DTS_QUEUE`, `DTS_RUNTIME` из этого набора, запустите API с собранным фронтом на 8091, затем запустите `qa-review-save.js`. Эти CSV никогда не используются для обучения, исследования качества или демонстрации реальных температур.

Workflow `web-checks.yml` повторяет клиентские/серверные проверки и браузерный путь на этих изолированных fixtures. Все пять браузерных сценариев также прошли в отдельном Linux-контейнере с Python 3.12 и скачанным Chromium; [отчёт репетиции CI](measurements/browser-ci-linux.json). В конфигурации `scripts/playwright-ci.json` явно выбран bundled Chromium, поэтому системный Chrome на runner не требуется. Проверено, что исключение в `run-code` даёт ненулевой exit code. Запуск GitHub Actions требует загрузки коммита на GitHub; локальная репетиция не является успешным удалённым запуском CI.

Для 30-минутного замера откройте `/research?record=5` с `--idle-timeout=0`, задайте нужный viewport и запустите `qa-replay.js`. Итог находится в `window.__dtsSoak` после `done=true`. Сразу после запуска включите сборщик в другом терминале:

```powershell
.venv/Scripts/python.exe scripts/collect-replay.py --session qa --output .runtime/replay-final.json
```

Он каждые 30 секунд атомарно сохраняет промежуточный JSON, затем завершится после полного отчёта. Сборщик должен использовать тот же `--package`, что и команда открытия CLI: по умолчанию это `@playwright/cli@0.1.22`. Не переключайте вкладку и не перезапускайте сервер во время замера. Сохранение только в памяти вкладки ненадёжно: при первом финальном замере после вынужденного перерыва закрытие сессии по idle timeout уничтожило итог, поэтому введён дисковый сборщик и повторная проверка.

## Проверка расширения от 9 октября 2026

TypeScript, ESLint, production-сборка и 5 клиентских тестов прошли. Сервер: 12 тестов, включая проверку всех шести реальных записей, независимых журналов, HTML-экранирования, неверного source SHA, повреждённого исследовательского пакета и восстановления постоянной истории. OpenAPI и сгенерированные TypeScript-типы согласованы.

Адаптер проверил 340 окон `real-data-v2`, shortlist из 24 и 13 956 989 исходных ячеек. Окна перекрываются; это число проверок, а не число уникальных измерений. Слабые предложения из пакета не импортируются как ответы или обучающие метки.

Полный новый браузерный путь прошёл в Chromium, Firefox и WebKit: пакет, сравнение реального профиля, HTML-экспорт, закладка, восстановление ссылки, IndexedDB-черновик, независимое раскрытие методов (403 для другого имени), сохранение и мобильные шаги. Отчёты: [Chromium](measurements/workbench-chromium.json), [Firefox](measurements/workbench-firefox.json), [WebKit](measurements/workbench-webkit.json). Chromium повторён после итоговых изменений контрактов; Firefox/WebKit проверялись на предыдущей сборке этого расширения. Размеры 320, 390, 430, 1024, 1440 px не дали горизонтального переполнения. Это эмуляция размеров на компьютере.

Пять существующих CI-сценариев повторно прошли локально на новых изолированных контрактных fixtures: каталог/срезы, сохранение с сетевой ошибкой и конфликтом, replay, WebGL fallback/клавиатура, отмена устаревших запросов. Дополнительно реальный перезапуск QA API сохранил ревизию и дал ровно один отказ старого токена перед его обновлением. Эти технические ответы не попали в рабочий журнал 8081. GitHub Actions этим локальным запуском не заменён.

[Полный цикл демонстрации](measurements/demo-cycle.json): Windows, Chromium 154, viewport 1440×900, loopback Docker, 310 секунд, 63 замера, все 24 окна, 0 runtime errors. JS heap 8,77–19,42 MB, максимум бинарного LRU 3 244 680 байт (3,09 MiB), максимум 3 Canvas. GPU-счётчик отражает запрошенные buffers/textures и одну RGBA-поверхность, не реальную VRAM. Замер сделан перед небольшими финальными изменениями реестра методов и мобильного контекста; это не 30-минутный soak итоговой версии, не измерение FPS/INP и не доказательство плато всей памяти процесса.

PNG итоговых экранов и инструкция показа находятся в [DEMO_AND_RESULTS.md](DEMO_AND_RESULTS.md). Автопереход останавливается при работе с полями участка, чтобы не потерять ввод пользователя.

Измерения настоящего телефона, целевого INP, 60/30 FPS под нагрузкой, длительного перемещения по множеству участков и полного resident memory сервера/браузера ещё нужны перед общим стендом. Локальный тест одного replay не заменяет эти нагрузки.
