# Светлая и тёмная темы

Действующий контракт интерфейса с 15 октября 2026. Пользователь явно поручил обе темы **на всём сайте**, включая лендинг и авторизацию. Это цветовые режимы одного UI: состав страниц, тексты, навигация, порядок экранов и данные сохраняются.

## Как пользоваться

В шапке есть кнопка с луной/солнцем. Доступное имя — «Тёмная тема», состояние объявляется через `role="switch"` и `aria-checked`. Работает мышью, Enter и Space; зона нажатия 44×44 px. На странице входа и ошибке соединения кнопка находится сверху формы. В полноэкранном показе кейса кнопка доступна внутри полноэкранного блока.

При первом открытии используется настройка ОС. Явный выбор сохраняется в `localStorage['dts-ui-theme']` (`light` или `dark`), действует для всего origin и синхронизируется между вкладками. Это только оформление: аккаунты, ответы, измерения и токены доступа туда не записываются. При запрете или переполнении хранилища переключение работает в текущей вкладке; постоянное сохранение тогда не гарантируется. Выбор другого устройства автоматически не переносится.

Тема применяется ранним скриптом в `index.html`, до запуска React. Bootstrap и приложение используют одинаковый приоритет: явный выбор → ОС. Удаление предпочтения возвращает следование ОС; отдельного третьего оформления нет.

## Реализация

| Файл | Ответственность |
| --- | --- |
| `apps/web/src/theme-model.ts` | Проверка предпочтения, безопасное чтение/запись |
| `apps/web/src/theme.tsx` | Общий контекст, Carbon GlobalTheme, переключатель, события ОС/другой вкладки, разрешённые цвета Canvas |
| `apps/web/src/theme.scss` | Carbon Gray 100, семантические поверхности, подписи и состояния |
| `apps/web/src/styles.scss` | Общие потребители токенов и Carbon White |
| `apps/web/index.html` | Цвет до загрузки JS/CSS, meta theme-color |
| `apps/web/src/theme-model.test.ts` | Приоритет, недоступное хранилище и согласованность bootstrap |

Темы основаны на установленном Carbon: [принципы цветов и слоёв](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview). White: страница `#fff`, панель `#f4f4f4`; Gray 100: страница `#161616`, панель `#262626`, вложенная поверхность `#393939`. Основной текст и ссылки берутся из `--cds-text-*` / `--cds-link-*`. Основная кнопка использует **button-primary**, а не цвет ссылки. Шапка намеренно тёмная в обоих режимах.

**Порядок Sass важен:** `@use "./theme" as app-theme` следует после импортов используемых компонентов Carbon. Их токены регистрируются при импорте. Иначе фон/текст станут тёмными, а кнопки могут сохранить значения White. Не «чинить» это ручной палитрой для каждой кнопки.

Уведомления Carbon по умолчанию инверсные: в Gray 100 они могут быть светлыми. В этом продукте локальные inverse-токены внутри `.cds--inline-notification` связываются с тёмной поверхностью и семантическими цветами статуса. Текст, иконка, граница и состояние закрытия остаются читаемыми.

## Правила для новых экранов, в том числе Pipeline

1. Не создавать отдельные light/dark-компоненты и не менять маршруты при смене темы. Не добавлять `key={theme}` на приложение или страницу: это потеряет несохранённый контекст.
2. Фон страницы — `--dts-page-background`, панель — `--dts-panel-background`, вложенная поверхность — `--dts-surface-background`. Текст, границы, ссылки, поля и состояния — роли Carbon или существующие семантические токены. Не писать `background: white` / `color: black` в новом блоке.
3. Не применять `filter: invert()`, глобальные фильтры, отдельную палитру экрана или CSS, который скрывает ошибки и переполнение.
4. Canvas/uPlot получают разрешённые цвета через `chartColors()`. Смена `useAppTheme().theme` пересоздаёт только нужный линейный график с очисткой старого объекта и worker. WebGL-поле перерисовывается без повторной загрузки матрицы и без создания нового контекста.
5. SVG для подписей, сетки и линий используют семантические CSS-переменные; подпись и легенда должны совпадать с линией.
6. Cividis, маска пропуска, числовые шкалы, знак разности и scientific palette не инвертируются. Светлая ячейка отсутствующих измерений — условный знак данных, не светлая форма. Логотипы остаются исходными изображениями.
7. Тема не запускает расчёт, не меняет источник/SHA/run_id, окно, выбранную точку, экспертный ответ, права или API. Не выполнять запросы записи ради переключения оформления.
8. Проверять **обе** темы: загрузка, пустое состояние, готовые данные, ошибки, disabled, hover/focus, меню, таблицы, точные графики и мобильная ширина. Новое состояние не принимается только по первому скриншоту.

Старые сохранённые кейсы и автономные ZIP/HTML остаются побайтно прежними. Переключатель оформляет действующие страницы сайта; он не переписывает архивные документы.
