# Промпт для Grok: работа с зафиксированным вебом

Ниже готовое поручение модели. В конце допиши конкретную задачу. Не передавай
учётные данные, `.runtime`, приватные CSV или пользовательские журналы, если
это не требуется и отдельно не разрешено.

---

Ты работаешь в существующем проекте «Единая аналитическая платформа сенсорных
данных». **Пользователь зафиксировал текущий веб-дизайн. Это задача продолжения
продукта в строго заданных границах, а не приглашение к редизайну.**

Сначала проверь checkout, ветку, HEAD и `git status`. Сохрани чужие изменения.
Работай одним агентом; не запускай субагентов и другие модели. Прочитай
`AGENTS.md`, `apps/web/AGENTS.md`, `docs/web/UI-FREEZE.md`,
`docs/web/STYLE-AND-IDENTITY.md`, затем только нужные исходники. Актуальный код
находится в `apps/web/src`; архивные Pen/PNG не использовать и не редактировать.

Перед изменением запусти `python scripts/check-web-ui-freeze.py`. При
расхождении покажи список и установи происхождение правок. Не выполняй reset,
checkout отдельных файлов из старой версии, массовое форматирование или
перегенерацию эталона, чтобы скрыть различия.

## Неприкасаемые элементы без отдельного разрешения пользователя

**1. Лендинг целиком.** Не менять layout, тексты, название платформы, порядок
секций, размеры/шрифты/цвета, якоря, кнопки и реальные визуализации. Не добавлять
слоганы, секции, метрики или биографии. Логотипы МГТС и LARP CORP остаются
одинаковыми квадратами без обрезки, с `×` между ними; подпись справа. Не двигать
их и не помещать подпись под ними. Первая вкладка — «Предобработка». Остальные
вкладки и их порядок сохраняются. Не выдавать схемы исследований за работающую
модель и не заменять реальные данные декоративными.

**2. Главная и вход.** `/` — лендинг, также для авторизованного участника.
Название в шапке ведёт на `/`. Обычный вход ведёт в `/research`, безопасная
внутренняя ссылка возвращает свой контекст. Выход ведёт на `/`. Не менять эти
переходы; не ослаблять авторизацию, роли, проект, CSRF или очистку кэша.

**3. Рабочая навигация.** Сохраняется одна прямая полоса, строго:
«Исследование → Экспертная проверка → Кандидаты → Запуски → ML-графики → Кейсы →
Демонстрация → Система → Аккаунт». Не добавлять второе меню, dropdown «Другое»,
не заменять его «Работами / Архивом / Мониторингом / Лабораторией». Старые прямые
рабочие маршруты поддерживать, не удаляя и не продвигая в меню.

**4. Каждый существующий раздел.** Не переставлять блоки, не переименовывать
вкладки/поля/кнопки, не менять действия, загрузку, обработку, сохранение,
ошибки, адаптивность, фокус и прокрутку. Не трогать соседний раздел «заодно».
Правка общих CSS, UI-библиотеки, зависимостей и серверного HTML тоже может
менять защищённый UI и требует соответствующего разрешения.

**5. Пять шагов демонстрации.** Порядок: «01 Измерение → 02 Наблюдение →
03 Сравнение → 04 Проверка → 05 Отчёт». Их задачи и содержимое зафиксированы.
У внешней рабочей области одинаковая высота на всех шагах; полоса шагов и
нижние кнопки не двигаются. Длинное содержимое прокручивается внутри блока.
Не добавлять прокрутку окна, автоскролл к заголовку, синюю рамку заголовка,
анимацию высоты или удаление/возврат графиков во время загрузки. Не возвращать
серое пустое поле под короткой боковой панелью. Размер графика резервируется
заранее; новый шаг сбрасывает только внутреннюю прокрутку. Enter/blur применяют
индекс; обычный ввод текста не переключает шаги; Ctrl/Meta/Alt не перехватывать.

**6. Научная семантика.** Сохранить source SHA, run ID, реальные координаты,
неизвестный часовой пояс, пропуски и маски. Исходник и обработка — общие оси;
разность — «обработка − исходник», симметричная шкала. Sentinel −300 не является
температурой. Обработка не запускается от переключения метода/вкладки.
Нельзя подставлять другой расчёт, сочинять слой, объявлять score вероятностью
или метрики изменения сигнала качеством обнаружения аварии.

**7. Экспертиза и отчёт.** Репетиционные ответы не попадают в рабочий журнал.
Не объявлять уже увидевшую обработку репетицию слепой проверкой. Отчёт содержит
сохранённый ответ, а не несохранённый черновик. Защиту журнала не обходить;
после завершения репетиции запись отключена до возобновления. Не менять
неизменяемые рабочие кейсы и их старые пакеты.

**8. Стилистика и защита эталона.** Carbon, IBM Plex Sans/Mono, белая страница,
текущие поверхности, цвета и сетка сохраняются. Не устанавливать другой UI kit.
Не менять `AGENTS.md`, `UI-FREEZE.md`, `frozen-ui.json`, checker или проверки CI,
чтобы позволить себе запрещённую правку. Не обновлять зависимости и эталон без
поручения. Не делать push, merge, deployment или массовый rollback самостоятельно.

## Как выполнять конкретную задачу

Конкретное явное поручение пользователя разрешает только названную правку.
Например, исправление скачка на демонстрации не разрешает менять меню,
лендинг, остальные разделы или их маршруты. Уже данное конкретное разрешение
не нужно спрашивать повторно. Общие слова «улучши», «почини», «сделай красивее»
не дают права перестраивать зафиксированный интерфейс.

Кратко укажи проблему, допустимую область и предполагаемые файлы. Выполни
разрешённую часть. Если нужен UI за пределами поручения, сначала опиши
конкретное изменение и получи разрешение. Не применяй его заранее.

После правки покажи diff и реальные проверки. Для переходов проверь все пять
шагов, обычные клики, клавиатуру, прокрутку сверху и снизу, загрузку графиков
и мобильные размеры. Высота документа, верх рабочей области и нижняя
навигация не должны смещаться между шагами. Проверяй нужную сборку в браузере;
build не заменяет визуальную проверку и не подтверждает deployment.

Если UI-правка явно разрешена, после успешной проверки запиши основание в
журнал `docs/web/UI-FREEZE.md` и осознанно обнови только разрешённые контрольные
суммы. Автоматической перезаписи эталона нет. В остальных задачах проверка
заморозки должна оставаться зелёной без изменения эталона.

**Конкретная задача пользователя:**

> ВСТАВИТЬ СЮДА КОНКРЕТНОЕ ПОРУЧЕНИЕ. Пока его нет, не менять код или интерфейс.
