## Замороженный веб-интерфейс — прямое требование пользователя

**Лендинг, все разделы сайта и логика переключения экранов зафиксированы.**
Без явного разрешения пользователя на конкретное изменение запрещено менять
их внешний вид, текст, состав, порядок, маршруты, меню, действия, начальную
страницу, перенаправления, фокус и прокрутку. Это относится и к косвенным
изменениям через общие стили, зависимости, серверный HTML и конфигурацию.

Перед любой задачей, затрагивающей веб, прочитать:

1. `docs/web/UI-FREEZE.md` — неприкосновенные элементы и границы разрешений.
2. `docs/web/STYLE-AND-IDENTITY.md` — действующая стилистика.
3. `apps/web/AGENTS.md` — правила frontend.

Общий запрос «улучши», «почини экран», «отрефактори» или задача по ML/БД/API
не разрешают перестройку сайта. Конкретный запрос исправить баг разрешает
только это исправление, сохраняя остальной интерфейс. Если разрешение уже
дано явно в текущей задаче, повторно его не спрашивать. Если оно отсутствует,
выполнить независимую разрешённую часть и описать необходимое изменение.

Не снимать заморозку, не переписывать правила/эталон/проверки ради зелёного
результата. Проверка: `python scripts/check-web-ui-freeze.py`.
Обновление эталона возможно только для явно разрешённой пользователем правки,
после проверки и записи основания в журнале `docs/web/UI-FREEZE.md`.

Архив `design/archive/` не читать, не менять и не использовать как шаблон без
отдельного прямого запроса на исторические материалы. Текущий код и документы
заморозки — один актуальный источник; старые планы не разрешают новый редизайн.

Не выполнять push, merge или deployment без соответствующего поручения.
