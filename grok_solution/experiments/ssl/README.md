# ssl

Слепой автоэнкодер поля \(T(t,x)\): дырка 8×16, четыре направления, Хьюбер по маске, без меток. Код: `experiments/ssl/ssl.py` (`BlindSpotAE`, `score_field`), обучение `experiments/ssl/train_ssl.py`, вес `artifacts/stage1/ssl_ae.pt`. Скор — ошибка восстановления. В `scripts/predict.py` ветка `--method ssl_ae` импортирует `experiments.ssl.ssl` лениво, наверх импорт не поднимается.

Это не CA-TCC. `dts/semi_contrastive.py` остаётся в ядре.

## Цифры

`artifacts/eval/stage1_v8_round2.json`, порог с val.

| точка | val IoU | val FAR | test IoU | test FAR |
| --- | ---: | ---: | ---: | ---: |
| far_1e-3 | 0.000354 | 0.001000 | 0.002311 | 0.001589 |
| far_ref | 0.028525 | 0.058082 | 0.022490 | 0.149335 |

Тот же test при far_1e-3 в `artifacts/eval/unsup_real.json` → `supervised_synth_published.ssl_ae`: IoU 0.002311, F1 0.004612. Рядом в том объекте U-Net 0.3625 и `ens_unet_tcn_lgbm` 0.4025.

`docs/UNSUP.md` прямо называет причину нуля: дырка уже типичного hotspot (медиана v8 около 6 строк на 37 точек, дырка 8×16), сеть видит очаг сбоку и закрашивает центр. `PROGRESS_LOG.md` фиксирует провал этапа 1: SSL-автоэнкодер IoU около 0.002, «восстанавливает и события».

## Почему отклонён

При FAR \(10^{-3}\) детектор почти не пересекается с событиями: test IoU 0.002 против 0.363 у U-Net того раунда и 0.405 у победителя. Ошибка восстановления не отделяет очаг от фона, если контекст вокруг дырки уже содержит событие. В члены `ens_u2ft_tcn_lgbm` автоэнкодер не входит. Повторно учить его на шести CSV нельзя: это была синтетическая модель, а реальные файлы остаются только оценкой.
